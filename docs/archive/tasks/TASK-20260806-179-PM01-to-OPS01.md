# TASK-179: ALLSTART must not hang forever

## Problem

Kurt reports `ALLSTART.ps1` getting stuck mid-bring-up. After OPS-178, Hermes
often ForceRestarts when MCP `python.exe`→`pythonw.exe` is rewritten. That path
calls `hermes gateway stop` with **no timeout**; MCP children can keep stop
blocked forever. ALLSTART uses `Start-Process -Wait` on Hermes (and similarly
Tailscale / Voice), so the whole launcher freezes.

## Solution

1. `start-hermes.ps1` `Stop-HermesOnPort`: run `hermes gateway stop` with a short
   timeout, then force-clear `:8642` listeners.
2. `ALLSTART.ps1`: wrap Hermes / Host / Tailscale / Voice child scripts in
   `WaitForExit` deadlines; add `-SkipHermes` / `-SkipVoice`.
3. Voice STT/TTS health probes: shorten so CUDA load cannot look like a hang.

## Acceptance

| # | Criterion |
| --- | --- |
| 1 | Stuck Hermes stop cannot freeze ALLSTART > `HermesTimeoutSec` (default 90s) |
| 2 | Voice / Tailscale soft-fail on timeout; Host + ChatDesktop still launch |
| 3 | `-SkipHermes` / `-SkipVoice` recovery path documented |
| 4 | Kurt Windows re-verify: fresh ALLSTART reaches ChatDesktop |
