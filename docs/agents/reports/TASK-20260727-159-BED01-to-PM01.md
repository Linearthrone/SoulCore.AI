# TASK-20260727-159 BED-01 Completion Report

## Verdict: **Pass**

Nested workflow tool dispatch no longer uses empty `{}` when the target
tool needs arguments. `workflow_execute` resolves args from optional
`step.args` and/or maps `step.description` into the tool's primary string
parameter (`recall_memory`→`query`, `speak`→`text`, schema fallback).
ISSUE-005 marked **Fixed**.

## Root cause (confirmed)

BED-141 `WorkflowExecuteTool` always called:

```csharp
registry.ExecuteAsync(toolName, EmptyToolArgs /* {} */, ct)
```

QA-142 AC6 failed because `recall_memory` / `speak` require string args.

## Fix

| Piece | Behavior |
| --- | --- |
| `WorkflowStep.Args` | Optional JSON object persisted in `steps_json` |
| `workflow_create` | Accepts `steps[].args`; rejects non-object |
| `WorkflowStepToolArgs` | Merge explicit args + description fill (known aliases + JSON Schema `required` / preferred string names) |
| `workflow_execute` | Dispatches resolved args; surfaces `tool_args` in step `Data` |

### Resolve order

1. Copy `step.args` object properties (if present).
2. If `description` is non-empty and the primary string slot is unset:
   - known alias (`recall_memory`→`query`, `speak`→`text`, …), else
   - first preferred ∩ required string from tool schema, else
   - any required string, else preferred optional string.
3. If nothing to fill → `{}` (tools with empty parameter schemas).
