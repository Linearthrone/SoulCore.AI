Two consequences:

1. `animation_mode` is `ANIMATION_BLUEPRINT` but `anim_class` is `None`, so `GetAnimInstance()` returns null.
   `PlayAnimation` will log `"PlayAnimation: no AnimInstance on ..."` and return before touching the montage.
   The post-process AnimBP does not help — it is a separate instance and is not what `GetAnimInstance()` returns.
2. No existing gameplay AnimBP contains a `DefaultSlot`. Even once an AnimBP is assigned, its AnimGraph needs a
   Slot node named `DefaultSlot` or the montage will play internally with no visible output.

Both belong to the Character/AnimBP owner (BED-114–117 / BED-120), not to this asset ticket. Flagging so
QA-123 is not scheduled expecting a visible wave before that lands.
