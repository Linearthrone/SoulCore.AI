## Blocker: UE 5.8 Remote Control cannot bind UObject function parameters

### Symptom

Every call to `/remote/object/call` for a function that takes a `UObject`-typed
parameter returns **HTTP 400 with an empty body**, regardless of the value
supplied. No-arg functions succeed.

### Evidence matrix

| Function | Args | Result |
|---|---|---|
| `LevelEditorSubsystem.EditorRequestBeginPlay` | (none) | **200** — PIE started |
| `LevelEditorSubsystem.IsInPlayInEditor` | (none) | **200** `{"ReturnValue": true}` |
| `KismetSystemLibrary.UnregisterForRemoteNotifications` | (none) | **200** |
| `KismetSystemLibrary.ExecuteConsoleCommand` `Command="help"` | `WorldContextObject` (UObject) | **400** (empty body) |
| `KismetSystemLibrary.ExecuteConsoleCommand` `Command="py ..."` | `WorldContextObject` (UObject) | **400** (empty body) |
| `LevelEditorSubsystem.GetExactCameraView` | `ViewportConfigKey` (FString) | **400** (empty body) |
| `EditorActorSubsystem.GetAllLevelActors` (on guessed path) | (none) | **404** (wrong object path; subsystem not addressable) |

### Variants tried (all 400)

For `ExecuteConsoleCommand`:
- `WorldContextObject` omitted / empty string `""`
- `WorldContextObject = "/Engine/Transient.UnrealEditorEngine_0"` (the README/BOB-script default)
- `WorldContextObject = "/Script/Engine.Default__UnrealEditorEngine"`
- `WorldContextObject = "/Script/Engine.Default__GameModeBase"` (resolvable CDO)
- `WorldContextObject = "/Script/Engine.Default__WorldSettings"` (resolvable CDO)
- `WorldContextObject = "/Script/LevelEditor.Default__LevelEditorSubsystem"` (resolvable CDO)
- `SpecificPlayer` omitted vs `null` vs `""`
- `generateTransaction` true vs false
- Raw JSON body (parameters as real JSON object, not string)
- `/remote/batch` endpoint

### Root cause

UE 5.8 Remote Control's `/remote/object/call` cannot bind `UObject`-typed
function parameters from string paths in this editor configuration. Property
read/write on CDOs works (properties use a different code path), and no-arg
functions work, but any function with a `UObject` parameter is rejected with
400. `ExecuteConsoleCommand`'s `WorldContextObject` is `UObject`
(`/Script/CoreUObject.Object`), so the `py <script>` console command — the
ticket's intended execution path — is not invokable via RC here.

The transient preset route (`/remote/preset/transient`) was attempted, but the
auto-generated preset names (`TransientRCPreset0/1`) returned 404 on the
`/remote/preset/<name>/function/...` and `/expose/property` routes, so
exposing+calling through a named preset did not succeed either.

### What did NOT work to unblock

- Starting PIE first (in case the transient WorldContextObject needed a play world): PIE is running; 400 persists.
- Resolvable CDO object paths as `WorldContextObject`: still 400.
- The `/remote/batch` endpoint: 400.
- Addressing the `EditorActorSubsystem` / `PythonScriptingSubsystem` by remote object path: 404 (those subsystems are not exposed via RC on this editor).
