### HTTP contract (LLMOD)

Mirrors `LLMOD-max-master/MCPServer/http_server.py`:

```
POST http://housevictoria:8080/command
Content-Type: application/json

{
  "command": "mt4_status",
  "parameters": {}
}
```

Response shape:

```json
{
  "success": true,
  "message": "Command executed successfully",
  "data": "{\"success\":true,\"bridge_active\":true,...}"
}
```

`LlmodHttpMt4Bridge` parses stringified `data` JSON and surfaces inner `message` (or raw JSON) as `ToolResult.Content`.

### Parameter mapping (SoulCore → LLMOD)

Hermes previously relied on LLM routing. Direct HTTP requires explicit mapping in `Mt4LlmodArgsMapper`:

| Tool | SoulCore args | LLMOD params |
| --- | --- | --- |
| `mt4_execute_trade` | `direction`, `sl`, `tp` | `trade_type` (0/1), `stop_loss`, `take_profit` |
| `mt4_run_backtest` | `ea`, `from`, `to` | `strategy_name`, `start_date`, `end_date` |
| `mt4_export_history` | `from`, `to` | `start_date`, `end_date` |
| `mt4_get_historical_bars` | `timeframe`, `count` | `time_frame`, `max_bars` |
| `mt4_get_market_data` | `symbol`, `timeframe` | `symbol` only |

**Gates unchanged (BED-138):** `AllowMt4Read` / `AllowMt4Trade` + per-trade `confirmed=true` + mandatory `sl` on `execute_trade` — enforced in `Mt4ToolBase` **before** any bridge invoke.
