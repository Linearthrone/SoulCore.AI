# TASK-20261014-212 — FED-01 report

A wheel on her screen now seats the guest pointer in the center column, left-clicks there, then queues a Page key the guest can take. One positive detent is Page Up make `E0 49`, about 40 ms, then break `E0 C9`. One negative detent is Page Down make `E0 51`, the same gap, then break `E0 D1`. Before those taps, once per wheel, the modifier-release prefix `AA B6 9D B8 E0 DB` goes out as its own `putScancodes` array.

The seat is one `PutMouseEventAbsolute` at the framebuffer center (`width / 2`, `height / 2`) with `dz=0`, then left button down and button up at that same point. The live guest size is used when Presence has it. Otherwise the seat is the 1280×800 default, `640,400`. The Windows cursor is not parked. No mouse-wheel `dz` is sent.

`sent` is written only when VirtualBox's stored count equals the bytes handed over (prefix + make + break). One detent that stores all ten bytes logs `her-screen wheel notches=1 key=pageup seat=640,400 stored=10 sent`. A short count is a `COM error:` line with `stored=` on it, and it does not say `sent`. If `putScancodes` is missing, each byte uses `putScancode` and those stored counts are added up.

The live guest page was not checked. This seat does not send a wheel to the running desk, so this report does not mark the page as having moved.
