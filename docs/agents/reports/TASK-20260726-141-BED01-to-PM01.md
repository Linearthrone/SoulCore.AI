## Execute semantics

| Mode | Behavior |
| --- | --- |
| `all=false` (default) | Execute **one** step at `current_step`, then increment. Returns that step's result + new `current_step`. |
| `all=true` | Execute **all remaining** steps in order; returns a text summary + `results[]` + final `current_step` / `complete`. |
| Reached end (`current_step >= steps.Count`) | `Success:false`, `Content:"workflow complete"` — soft completion, not a hard error. |

Per-step:

- **No `tool`**: description-only — `Success:true`, content is `step N: <description>`.
- **With `tool`**: dispatch via `IToolRegistry.ExecuteAsync(name, {})` (empty args object — step schema has no tool-args field). Content includes tool result.
- Nested `workflow_execute` / `workflow_create` as step tools are refused (recursion guard).
- Execution is **model-initiated only** — not wired into SoulLoop.

## DI note

`WorkflowExecuteTool` resolves `IToolRegistry` lazily via `IServiceProvider`
(same pattern as `ListToolsTool`) so Host construction does not cycle
`ToolRegistry → IEnumerable<ITool> → WorkflowExecuteTool → IToolRegistry`.
