## `tool_choice` default + configurability

- **Default**: `"auto"` (`HermesOptions.ToolChoice` default).
- **`"none"`**: model must not call tools (text-only turn). Test: `ToolChoice_None_IsSentOnTheWire`.
- **Specific tool**: JSON object string `{"type":"function","function":{"name":"..."}}` — passed verbatim on the wire. Test: `ToolChoice_SpecificToolObject_IsSentVerbatim`.
- **Empty tools**: when `tools[]` is empty, the client **omits** `tool_choice` entirely (OpenAI rejects `tool_choice` without `tools`). Test: `EmptyToolList_OmitsToolsAndToolChoice_ModelReturnsTextInOneRoundTrip`.
- Configured via `Hermes:ToolChoice` in appsettings (string). The method signature is fixed (byte-compatible), so per-call override of `tool_choice` is not exposed on the method; the host can change the configured value between turns if needed.

## Iteration cap — shared `MaxToolIterations`

- **Shared**: `HermesHttpClient` reads `InferenceOptions.MaxToolIterations` (default 8) via a new
  `IOptions<InferenceOptions>` ctor parameter. **No separate Hermes setting** — single knob for both
  Ollama + Hermes backends, per the dispatch instructions.
- Cap reached → returns `HermesHttpClient.IterationCapMarker` (when no assistant text was produced)
  or the last non-empty assistant text (when some text was produced before the cap). Same semantics
  as `OllamaInferenceClient.IterationCapMarker` (distinct constant so callers can tell which backend capped).
- Tests: `IterationCap_StopsAfterN_WhenModelKeepsCallingTools`, `IterationCap_ReturnsLastAssistantText_WhenModelEmittedSomeTextBeforeCap`.

## ISSUE-20260726-001 fallback parser — implemented

The known qwen2.5 flakiness (ollama #13968, #12174; confirmed empirically by BED-129): the model
sometimes leaks a tool call as **bare JSON in `message.content`** with `tool_calls: null`. Without
the fallback, the loop treats the leaked JSON as a normal text reply and Victoria silently fails to act.

### Implementation (in `HermesHttpClient.cs`)

1. Check `choices[0].message.tool_calls` first (OpenAI standard path).
2. If null/empty AND tools are advertised, call `TryRecoverToolCallsFromContent(content, toolNames)`:
   - **Fast path**: parse the whole `content` as a JSON object `{"name":"...","arguments":{...}}`.
   - **Slow path**: extract the first `{...}` object via brace-matching (`ExtractFirstJsonObject`),
     then parse it. Handles JSON embedded in prose (e.g. `"I'll call: {...} and reply."`).
   - Accept `arguments` as object or string form (defensive — same as the structured path).
3. If parse succeeds AND `name` matches a registered tool → dispatch it as a tool call (same path
   as structured `tool_calls`). The recovered call gets `id = "recovered_0"`.
4. If parse fails OR `name` is not a registered tool → treat as a normal text reply (no dispatch).
5. Log at **Information** level when the fallback fires: `"Hermes tool call recovered from content-embedded JSON at iteration {Iter} (count={Count})"`.
6. When no tools are advertised, the fallback is **not attempted** (a JSON object in content is
   never a tool call when the model has no tools).

### Unit test evidence

| Test name | Verifies |
| --- | --- |
| `FallbackParser_ContentEmbeddedJson_DispatchesTool_WhenToolCallsNull` | `content: '{"name":"echo","arguments":{"text":"hello"}}'` with `tool_calls: null` → tool dispatches, loop continues, final text returned. **The core ISSUE-001 test.** |
| `FallbackParser_JsonEmbeddedInText_DispatchesTool` | JSON embedded in prose text → extracted via brace-matching → dispatches. |
| `FallbackParser_NameNotRegistered_TreatedAsTextReply` | Leaked JSON with an unregistered `name` → treated as text reply (no dispatch, no crash). |
| `FallbackParser_NoToolsAdvertised_DoesNotAttemptRecovery` | No tools advertised → fallback not attempted → 1 round-trip, text returned. |

All 4 fallback tests pass.
