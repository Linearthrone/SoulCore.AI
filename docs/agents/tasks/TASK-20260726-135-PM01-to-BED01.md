# TASK-135: Desktop control tools + session opt-in gate

## Problem

LLMOD had `computer_use` (capture/click/type/scroll/key) + `list_desktop_windows` + `focus_desktop_window`. SoulCore has none. Restore desktop control as LLM-callable tools with a **session opt-in gate** (user must enable `AllowComputerControl` per session — never on by default).

## Security gate (mandatory)

| Action | Gate |
| --- | --- |
| `desktop_screenshot` (read-only capture) | Allowed when `Tools.AllowDesktopCapture=true` (default true — read is safe) |
| `desktop_click`, `desktop_type`, `desktop_scroll`, `desktop_key` (write/control) | **Session opt-in**: `Tools.AllowComputerControl=false` by default; user must set true per session (e.g. via a settings tab or chat command "allow computer control") |
| `list_desktop_windows`, `focus_desktop_window` | Allowed when capture allowed (read) |

Tools must refuse with `ToolResult(Success:false, Content:"desktop control requires user authorization — ask the user to enable AllowComputerControl")` when gate closed. The model is expected to ask the user to enable it.

## Do not

- Do not enable control tools by default — gate is closed out of the box.
- Do not implement browser tools (BED-136).
- Do not implement MT4 (BED-138).
- Do not bypass the gate from any code path.

## Solution

`ITool` implementations wrapping a desktop-control backend. **Two paths** per user decision "both backends":

1. **Hermes MCP** (`computer_use` MCP server, restored in OPS-143) — preferred when Hermes is up, routes through BED-144.
2. **Native C# fallback** (optional): `System.Drawing` capture + Win32 `SendInput` for click/type. Implement only if user wants native — document in report. If only Hermes path, mark native as out of scope and depend on OPS-143.

### Tools

```json
{ "name": "desktop_screenshot", "description": "Capture the desktop screen.", "parameters":{ "type":"object","properties":{ "monitor":{"type":"integer","default":0} } } }
{ "name": "desktop_click", "description": "Click at screen coordinates.", "parameters":{ "type":"object","properties":{ "x":{"type":"integer"},"y":{"type":"integer"},"button":{"type":"string","default":"left"} }, "required":["x","y"] } }
{ "name": "desktop_type", "description": "Type text at the current focus.", "parameters":{ "type":"object","properties":{ "text":{"type":"string"} }, "required":["text"] } }
{ "name": "desktop_key", "description": "Press a key (e.g. Enter, Escape).", "parameters":{ "type":"object","properties":{ "key":{"type":"string"} }, "required":["key"] } }
{ "name": "list_desktop_windows", "description": "List open desktop windows.", "parameters":{ "type":"object","properties":{} } }
{ "name": "focus_desktop_window", "description": "Focus a desktop window by title or index.", "parameters":{ "type":"object","properties":{ "title":{"type":"string"} }, "required":["title"] } }
```

### Config

```json
"Tools": {
  "AllowDesktopCapture": true,
  "AllowComputerControl": false,
  "DesktopBackend": "hermes" | "native"
}
```

## Acceptance criteria

1. All six tools implement `ITool`, register in DI, appear in registry.
2. Gate enforcement: with `AllowComputerControl=false`, `desktop_click/type/key` return `Success:false` with the authorization message; `desktop_screenshot` + `list_desktop_windows` work when `AllowDesktopCapture=true`.
3. `desktop_screenshot` returns image bytes (or path) the model can reference; content describes what was captured.
4. Hermes path: when `DesktopBackend=hermes` and Hermes up (OPS-143), tools route through `IHermesClient`/MCP. Document the request flow.
5. Native path (if implemented): uses `System.Drawing` + `SendInput`; document. If skipped, depend on OPS-143 and mark native out of scope.
6. Unit tests: gate closed refuses control tools; gate open allows them (mock backend, no real input injection in tests).
7. No tool may inject input when gate is closed — verified by test.
8. Report: file paths, gate logic, backend choice, unit test evidence, screenshot sample (if Hermes up).
