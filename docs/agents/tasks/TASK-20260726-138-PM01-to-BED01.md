# TASK-138: MT4 trading tools + per-trade confirmation gate

## Problem

LLMOD had 11 MT4 tools (`mt4_status/list_symbols/get_market_data/get_open_positions/execute_trade/close_position/verify_ticket/marketwatch_status/export_history/get_historical_bars/run_backtest`). SoulCore has none. Restore them as LLM-callable tools behind a **per-trade confirmation gate** — the highest-risk tool class in the proposal.

## Security gate (mandatory — highest risk)

| Action | Gate |
| --- | --- |
| Read tools (`mt4_status`, `list_symbols`, `get_market_data`, `get_open_positions`, `marketwatch_status`, `export_history`, `get_historical_bars`, `verify_ticket`) | `Tools.AllowMt4Read=true` (default false — even reads are gated by default; user opts in) |
| Write tools (`execute_trade`, `close_position`, `run_backtest`) | **Per-trade confirmation**: model calls the tool → Host **does not execute** → returns `ToolResult(Success:false, Content:"confirm trade: BUY 0.1 EURUSD at market? reply yes to confirm")` → model asks user → user confirms in chat (or via a settings confirm button) → Host executes on second call with `confirmed=true` |

**SL required**: `execute_trade` must require a `sl` (stop-loss) argument; reject without it.

**Never** auto-execute a trade from a single model call. The two-phase confirm is mandatory.

## Do not

- Do not enable MT4 by default — `AllowMt4Read=false` and `AllowMt4Trade=false` out of the box.
- Do not skip the per-trade confirmation for any path (including Hermes).
- Do not implement a paper-trading sandbox in this ticket (note as future work).
- Do not implement browser/desktop tools (BED-135/136).

## Solution

11 `ITool` implementations wrapping an MT4 bridge. **Hermes MCP** path preferred (`house_victoria` MCP `mt4_*` tools, restored in OPS-143); native C# MT4 client optional — document.

## Acceptance criteria

1. All 11 tools implement `ITool`, register, appear in registry.
2. With `AllowMt4Read=false`, all read tools return `Success:false` with authorization message.
3. `execute_trade` and `close_position` and `run_backtest` enforce two-phase confirm: first call without `confirmed=true` returns the confirmation prompt; second call with `confirmed=true` dispatches to MT4.
4. `execute_trade` rejects (returns `Success:false`) when `sl` is missing or invalid.
5. With `AllowMt4Trade=false`, even `confirmed=true` calls refuse — master gate.
6. Hermes path: routes through `IHermesClient`/MCP `mt4_*` when `Mt4Backend=hermes` and OPS-143 done.
7. Unit tests: all gate combinations covered; verify no execute call reaches the backend when gate closed or confirm missing.
8. Report: file paths, gate logic, two-phase flow, SL requirement, unit evidence. Note paper-trading sandbox as future work.
