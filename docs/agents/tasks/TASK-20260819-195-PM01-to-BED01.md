# TASK-195: Host Playwright browser for Victoria (Avenue A1)

## Problem

In-page Login hangs because the hot path is guest AT-SPI / screenshot → vision →
pixel click via Guest Additions. Kurt needs labeled UI in **seconds**, her cookies
on a **dedicated** profile (not his Chrome), VirtualBox **out of the web hot path**.

## Decision (PM accepts TT-193)

**Avenue A1 locked:** Host Microsoft.Playwright against Victoria-only `user-data-dir`.
Do **not** Playwright via guestcontrol per click. Do **not** attach Kurt's daily Chrome.

## Solution

1. New `PlaywrightBrowserBridge : IBrowserBridge` (Host process).
2. Persistent Chromium/`user-data-dir` under a SoulCore-owned path (coord OPS-198).
3. Tools (wire through existing `browser_*` or thin adapters — prefer extending
   `IBrowserBridge` so Call sites stay stable):
   - navigate (waitUntil load/DOM; Success only after load — see BED-194)
   - click by role/name (`getByRole` / getByText)
   - fill (she may type **her** passwords; **redact** values in logs/Content — SEC-197)
   - a11y snapshot (not full PNG as primary locator)
4. Config: `BrowserBackend=playwright` (or `native` remapped) when web workspace is on;
   GuestVmBrowserBridge **not** used for web Login when Playwright is available.
5. Expose a **frame/stream source** for FED-196 (CDP screencast or ≥2–5 fps JPEG pump
   of *her* page). Loopback only (SEC-004).
6. Tests: mock or headed CI-safe harness; no secrets in assertions.

## Do not

- Attach to Kurt's running Chrome / default profile.
- Invoke Playwright through VBox guestcontrol per action.
- Persist password/OTP frames to Presence gallery.
- Implement VS IDE (phase 2).
- Revive Hermes pixel computer_use as web actuator.
