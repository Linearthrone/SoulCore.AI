# TASK-20261014-193 — Victoria screen scroll

[Task] Operator mouse-wheel over Victoria’s embedded screen does not scroll the guest.

[Reference] VirtualBox `IMouse.putMouseEventAbsolute(x, y, dz, dw, buttonState)` — `dz` is vertical wheel. Clicks already park the Windows cursor because Mouse Integration clears events while the cursor sits over Presence (`VictoriaVmPointerPlan` remarks). Wheel does not.

## Problem

Scrolling the wheel while the pointer is over her screen does nothing in the Ubuntu guest.

## Root cause

Two gaps in the desk embed path. Both must be fixed.

1. **Wheel is not parked, so Mouse Integration clears it.**  
   `House/House.ChatDesktop/Services/VictoriaVmPointer.cs` (~144–159): a button press runs inside `WithCursorParked`. A wheel event calls `PutMouseEventAbsolute(ax, ay, notches, 0, 0)` with the Windows cursor still over Presence. The same integration that forced the click workaround drops `dz` before the guest paints a scroll.

2. **The overlay only sees `WM_MOUSEWHEEL` after a click.**  
   `House/House.ChatDesktop/Controls/HerScreenHwndOverlay.cs`: `ReportPointer` handles `WM_MOUSEWHEEL` (line ~416, delta/120 → notches) and `StaticWndProc` swallows it (~541–559). `FocusForTyping` runs only on button-down (~421). Windows delivers `WM_MOUSEWHEEL` to the focused window. If chat still has focus, the overlay never receives the wheel, so `HandleHerScreenPointer` in `MainWindow.BrowserView.cs` (~510–513) never posts.

`desktop_scroll` (xdotool button 4/5 in `VirtualBoxGuestAppLauncher`) is a different path. Do not change it.

## Solution

1. Inject wheel the same way as clicks: `WithCursorParked` around `PutMouseEventAbsolute` for a non-zero wheel. Move first (dz=0, dw=0, buttons=0), then send `dz`. Do not also click.
2. Deliver wheel when the pointer is over the embed even if another control has focus. On pointer move over the input HWND, focus that HWND (same `FocusForTyping` path), or an equivalent that still routes `WM_MOUSEWHEEL` into `ReportPointer`. Do not let the wheel fall through to the chat transcript.
3. `dz` unit: keep one Windows detent as one notch (`HIWORD(wParam)/120`, already in the overlay). If a parked ±1 is ignored by this guest, send ±120 (`WHEEL_DELTA`) and record which value the live guest actually scrolls on. Do not ship 120 if 1 already scrolls — 120 can jump many pages on Linux Guest Additions.
4. Direction: wheel rotated away from the operator scrolls guest content up (same as Windows). Negate `dz` only if a live check shows the opposite.
