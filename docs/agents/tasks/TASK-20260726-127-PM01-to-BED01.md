# TASK-127: Hermes tool-loop (`/v1/chat/completions` with `tools`)

## Problem

`HermesHttpClient.ChatAsync` posts to `/v1/chat/completions` with messages only. No `tools` field, no `tool_choice`, no `tool_calls` parsing. Cannot drive the LLMOD-style tool-loop through Hermes.

## Do not

- Do not restore the Hermes gateway itself (OPS-143 owns that — this ticket only updates the SoulCore C# client).
- Do not change `IToolRegistry` types (BED-125).
- Do not wire into `ChatWebSocketHandler` (BED-128).
- Do not assume Hermes is up — `Hermes.Enabled=false` must remain a valid config (gate the tool path behind `Enabled`).
- Do not implement concrete tools (BED-131+).

## Solution

Extend `HermesHttpClient` (and `IHermesClient`) to support OpenAI-compatible tool-calling:

### Request additions

```json
{
  "model": "local",
  "messages": [...],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "recall_memory",
        "description": "...",
        "parameters": { /* JSON Schema */ }
      }
    }
  ],
  "tool_choice": "auto"
}
```

### Response parse

OpenAI-compatible `tool_calls`:

```json
{
  "choices": [{
    "message": {
      "role": "assistant",
      "content": null,
      "tool_calls": [
        {
          "id": "call_abc",
          "type": "function",
          "function": {
            "name": "recall_memory",
            "arguments": "{\"query\":\"...\"}"
          }
        }
      ]
    },
    "finish_reason": "tool_calls"
  }]
}
```

Note: OpenAI `arguments` is a **JSON string** (not object) — parse with `JsonDocument.Parse`.

### Method signature

```csharp
public async Task<string> ChatWithToolsAsync(
    IReadOnlyList<ChatMessage> messages,
    IReadOnlyList<ToolDefinition> tools,
    CancellationToken ct);
```

Coordinate with BED-126 so both Ollama and Hermes paths share the same surface (`IInferenceClient` or a new `IAgentClient` — document the choice). Update `NullHermesClient` if interface extended.

### Loop (same shape as BED-126)

1. POST with `tools` + `tool_choice:"auto"`.
2. If `choices[0].message.tool_calls` non-empty → dispatch each via `IToolRegistry.ExecuteAsync` → append `{role:"tool", tool_call_id, name, content}` → re-POST.
3. Else return `choices[0].message.content`.
4. Cap iterations at `MaxToolIterations` (shared config with BED-126).

## Acceptance criteria

1. `ChatWithToolsAsync` sends `tools[]` + `tool_choice:"auto"`, parses `tool_calls`, dispatches via `IToolRegistry`, appends `role:"tool"` results with `tool_call_id`, re-posts, returns final text.
2. Iteration cap shared with BED-126 (`MaxToolIterations`).
3. Defensive `arguments` parse handles JSON-string form (OpenAI standard).
4. `Hermes.Enabled=false` or `NullHermesClient` returns deterministic stub without network.
5. `tool_choice` configurable (default `auto`; allow `none` / specific tool — document).
6. Unit test: mock HTTP layer, verify one tool round-trip; verify cap.
7. No regression to existing `ChatAsync` (non-tool path) — keep it for fallback / non-tool chat.
8. Report: method location, `tool_choice` default, evidence of one tool round-trip against a mock.
