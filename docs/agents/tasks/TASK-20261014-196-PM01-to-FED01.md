# TASK-20261014-196 — Wheel delivered, guest did not scroll

[Task] QA-195 Fail. One wheel-away detent hit `HerScreenInput` and the guest page did not move.

[Reference] `docs/agents/issues/ISSUE-20261014-001-her-screen-wheel.md` and the QA report above.

## What QA measured

Release ChatDesktop pid 4564. Guest `VMState=running` at 08:53:29 after `saved` then `aborted-saved`. At 08:58:40 `SendMessageTimeout` to hwnd `0xD0A2A` (`HerScreenInput`) returned 1 for `WM_MOUSEMOVE` and for `WM_MOUSEWHEEL` (`w=0x780000`, delta +120).

Guest lesson column best vertical shift **0** (error 16.997). Full frame best shift 0. `%LocalAppData%\HouseVictoria\presence-startup.log` was last written at 08:39:13 — no pointer fault at 08:58.

The chat crop moved 154px in a frame taken at 09:01:40, and that frame also has new lines. Do not treat that as proof the transcript stole the wheel. Do not change chat scrolling for this ticket.

## Root cause

`VictoriaVmPointer` opens one VirtualBox console lock on the STA thread and keeps it (`TryOpenConsole` in `VictoriaVmPointer.cs`). That lock was taken while the desk was up at 08:38. The guest was then saved (08:43), `aborted-saved` (08:50), and started again (running 08:53) by the desk's own `startvm`. The overlay still ran `ReportPointer` — the send returned 1 and `NotchesFromWheelDelta(120)` is 1 — but the queued `PutMouseEventAbsolute` went through the pre-save `IMouse`. A dead session did not throw, so `ReportFault` never wrote a line, and the framebuffer stayed put.

TASK-193's direct COM probe scrolled only before that save. Parking and `GuestWheelDz` are not the failure this time.

`HandleHerScreenPointer` can also drop a wheel with no log when `TryMapPointerStretchFill` returns null. QA could not see whether this wheel was posted.

## Solution

1. Before each pointer inject, if the locked machine is not `Running` or the console/mouse is gone, unlock and open a new shared lock. Do this on the same STA thread. Do not hold a session across a save / abort / start.
2. If `PutMouseEventAbsolute` throws, keep the existing fault log, drop the dead session, and retry the wheel once on a fresh lock.
3. Log one line per wheel to `presence-startup.log`: notches, mapped guest point or `dropped-unmapped`, and `sent` or the COM error. Do not log mouse-moves.
4. Leave `GuestWheelDz` as `-notches` (one detent, not ×120). Leave `desktop_scroll` alone.
