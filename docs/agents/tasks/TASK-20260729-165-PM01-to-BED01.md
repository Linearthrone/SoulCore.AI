# TASK-165: Forced-tool exclusivity (QA-142 AC6 wrong-tool escape)

## Problem

QA-142 Retest-2: `WorkflowToolIntent` + `ForceToolName` logs fire, but Ollama
still advertises the full `tools[]` under hard `tool_choice`. Models escape to
sibling tools (e.g. `task_list`) and Host executes them — AC6 `workflow_execute`
still Fail despite forceTool evidence.

## Solution

When `ToolLoopOptions.ForceToolName` is set (iteration 0):

1. Exclusive `tools[]` — advertise only the forced function.
2. Hard object-form `tool_choice` on Ollama `/v1/chat/completions` (unchanged path).
3. Never execute non-forced tool names — return `Success:false` refusal Content.

Keep BED-162 `WorkflowToolIntent` + BED-164 PreferHermes Avenue B intact.

## Acceptance criteria

1. ForceToolName iteration 0 → `tools[]` length 1 (forced name only) + tool_choice.
2. Model invents a non-forced name → registry not executed; refusal tool Content.
3. Later iterations restore full tools (auto).
4. WorkflowToolIntent + PreferHermes Avenue B regression green.
5. ISSUE-20260729-001 marked Fixed with unit evidence.
6. Report + push branch.
