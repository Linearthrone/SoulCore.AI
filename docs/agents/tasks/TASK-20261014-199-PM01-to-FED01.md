# TASK-20261014-199 — Sent wheel, page stayed

[Task] QA-198 Fail. The reconnect works. The page still does not scroll.

## What QA measured

Release pid 31092. `VMState=running`. `HerScreenInput` hwnd `0x310C58` at `5750,144 1221x683`. One `WM_MOUSEWHEEL` +120. After frame at 818 ms.

- Log: `her-screen wheel notches=1 point=754,371 sent`
- Guest full frame and body crop best shift **0**
- Chat shift **0**
- `CURSOR_BEFORE=2560,719` and `CURSOR_AFTER=2560,719`

The desk window is at `5116,0`. The Windows cursor was on the other side of that window for the whole check. `PutMouseEventAbsolute` returned, so `DeliverPointer` logged `sent`. The Firefox lesson in `tmpcode/qa-198/guest-before.png` did not move.

## Root cause

`InjectPointer` in `VictoriaVmPointer.cs` (~232–245) parks the cursor **outside** the desk, then sends two absolute events: a `dz=0` move, then `dz`. Mouse Integration reports the host pointer as out of range while it sits outside the VM window (`[-1,-1]` in `IMouse.putMouseEventAbsolute`). That report wins over the queued wheel, so the guest drops `dz`. The log still says `sent` because the COM call did not throw.

Clicks keep the outside park. Wheel must not use it. Point `754,371` is on the lesson page; the miss is the host pointer, not the mapping.

## Solution

1. Wheel is one call: `PutMouseEventAbsolute(ax, ay, dz, 0, 0)` with `dz = GuestWheelDz(notches)`. Delete the leading `dz=0` step for wheel.
2. While that call runs, put the Windows cursor **inside** the embed (center of the host window passed to `NoteHostWindow`), then restore it. Do not park outside for wheel.
3. Keep outside-park for button presses. Keep reconnect, the one log line, and `GuestWheelDz` as `-notches`.
4. Do not scale by 120 in this change.
