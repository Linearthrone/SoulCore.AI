## Acceptance criteria

1. **Hermes path chat**: with `PreferHermes=true`, a chat round-trip routes through `IHermesClient.ChatWithToolsAsync` (not Ollama); verify in host log.
2. **MCP tool call**: prompt Victoria to "take a screenshot of my desktop" (with `AllowComputerControl` / `AllowDesktopCapture` as needed) → model emits `tool_calls[0].function.name="desktop_screenshot"` (or the MCP name `computer_use`) → SoulCore routes through Hermes MCP → screenshot returns → model reports it.
3. **Browser**: prompt "capture my browser tab" → routes through `browser_bridge` MCP → returns capture.
4. **MT4 read**: with `AllowMt4Read=true`, prompt "what's my MT4 status?" → routes through `mt4_status` MCP → returns status.
5. **MT4 trade gate**: prompt "buy 0.1 EURUSD" → two-phase confirm enforced even on the Hermes path; `execute_trade` phase-1 returns the confirm prompt; phase-2 with `confirmed=true` + `sl` dispatches via `mt4_execute_trade` MCP.
6. **No silent fallback**: when Hermes is stopped mid-test, a tool call returns `Success:false` "hermes gateway unavailable" (no fallback to native unless `Backend=auto` — which is not the default).
7. **Regression**: native Ollama path still works — toggle `PreferHermes=false`, run a recall_memory chat, verify it routes through Ollama (BED-126) and still Passes QA-130 behavior.
8. **No double backend**: a single chat turn uses exactly one inference backend (Hermes XOR Ollama), not both.
9. Evidence in report: prompts, raw `tool_calls` from Hermes, MCP server logs (or Hermes logs showing the MCP dispatch), screenshot paths, MT4 dispatch log, Pass/Fail. File ISSUE on any failure.
