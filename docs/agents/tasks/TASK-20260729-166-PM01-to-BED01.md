# TASK-166: Ollama `/v1` ForceTool — stringify `arguments`

## Bug

Ollama ForceTool path uses `/v1/chat/completions`. When session history includes
prior assistant `tool_calls` whose `function.arguments` are JSON **objects**,
Ollama returns 400:

`cannot unmarshal object into Go struct field .messages.tool_calls.function.arguments of type string`

This blocks QA-142 AC5–7 after BED-165 (exclusive ForceTool works, but `/v1`
400 → no dispatch).

## Fix

In `SoulCore.Inference/OllamaInferenceClient.cs` (and any message builders for
`/v1`), serialize `arguments` as a JSON **string** on the wire when posting to
`/v1`. Keep BED-165 `FilterToolsByName` + refuse; BED-162 `WorkflowToolIntent`;
BED-164 Avenue B intact.

Add unit test proving outbound `/v1` body stringifies object arguments from
history.

   carried object-form args.
2. BED-165 exclusivity + refuse still green.

4. ISSUE-20260729-001 marked Fixed with unit evidence.
