# TASK-169: MT4 belongs to LLMOD — port into SoulCore, run on shadow

## User decision (2026-07-30)

1. **MT4 bridge is LLMOD, not Hermes.** Hermes was only transport. Stop treating Hermes as the owner of trading.
2. **MT4 terminal lives on `housevictoria` (shadow PC)** — same topology as the Unreal body: soul on main, body/tools that need Windows desktop software on shadow.
3. Port / wire so SoulCore Host (main) can call the LLMOD bridge without requiring Hermes MCP as the source of truth.

## Required design (BED chooses A or B; document in report)

### Option A — Preferred: LLMOD HTTP edge on shadow

Expose LLMOD’s existing MCP HTTP (`localhost:8080` / `mt4_*`) **or** a thin wrapper around `MetaTrader4Service` on **shadow** via Tailscale MagicDNS `housevictoria`.

SoulCore adds `IMt4Bridge` implementation e.g. `LlmodHttpMt4Bridge` / `NativeMt4Bridge`:

- `Tools:Mt4Backend = llmod` (or `native`) → HTTP to `http://housevictoria:8080/...` (exact path in report)
- Hermes path remains optional fallback only when `Mt4Backend=hermes`
- Default in `appsettings` becomes **llmod** (not hermes) once smoke-green

### Option B — Port C# file-bridge into SoulCore

Copy/adapt `MetaTrader4Service` (+ helpers) into `SoulCore.Inference` / new project, talking SMB/remote path to shadow `MQL4\Files\HouseVictoria`. Only if Option A is blocked. Document why.

**Do not** re-implement EA protocol from scratch if LLMOD already has it.

3. With `AllowMt4Trade=false`, `execute_trade` still refuses (gate message).

6. Unit tests: new bridge refuses when URL down; Hermes path regression still green when `Mt4Backend=hermes`.
7. Report: shadow Tailscale target used, ports, EA path on shadow, sample `mt4_status` JSON.
