# TASK-156: Best-effort SpeakAsync after chat (do not share dying CT)

## Problem

QA-130 Phase A tool-loop **Pass**, but **AC7 Fail**: after a successful reply, `SpeakAsync` was never called because `RequestAborted` cancelled at emotion `GetAsync` (client/episodic path) before speak. UE being down is separate — speak should still be *attempted* / logged even when Unreal is disconnected (Null/stub client).

## Do not

- Do not change tool-loop / recall_memory behavior.
- Do not require UE connected for Pass on this ticket.
- Do not break Strategy A keyword fallback.

## Solution

In `ChatWebSocketHandler` post-reply path (~`SpeakAsync(reply, cancellationToken)`):

1. Use a **best-effort** token for side effects after `chat.done` is sent (e.g. `CancellationToken.None`, or a linked token that ignores client abort for speak/emotion snapshot).
2. Ensure emotion `GetAsync` used only for speak/emotion side effects does not abort the whole post-chat pipeline when the WS CT is cancelled.
3. Log speak attempt outcome (success / unreal down / cancelled) distinctly.
4. Add a regression test that simulates aborted CT after reply and still observes SpeakAsync invoked on a recording unreal stub.

## Acceptance

1. With recording `IUnrealVerbClient`, aborted request CT after successful chat still records `SpeakAsync`.
2. `dotnet test` Pass; evidence in report.
