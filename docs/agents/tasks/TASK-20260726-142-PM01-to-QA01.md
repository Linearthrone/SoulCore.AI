# TASK-142: Phase E exit gate — task/workflow

## Context

Phase E clears when Victoria can create a task, query it, update its status, and create a workflow that calls a tool — all by her own decision.

## Test environment

- Host + Ollama `qwen2.5:14b`
- Task tools (BED-140) + workflow tools (BED-141) registered
- SQLite memory DB with `victoria_tasks` + `victoria_workflows` migrations applied

## Acceptance criteria

1. **Create**: prompt "create a task to remember to review the charter" → model calls `task_create`; verify a row lands in `victoria_tasks` with `status='todo'`; model reports the id.
2. **Get**: prompt "what's the status of that task?" → model calls `task_get` with the id; reports the status.
3. **Update**: prompt "mark that task done" → model calls `task_update_status` with `status='done'`; verify row updated.
4. **List**: prompt "list all my tasks" → model calls `task_list`; reports the list.
5. **Workflow**: prompt "create a workflow to: 1) recall a memory, 2) speak the memory" → model calls `workflow_create` with 2 steps; verify row lands.
6. **Execute workflow**: prompt "run that workflow" → model calls `workflow_execute` with `all=true`; step 1 calls `recall_memory` (via `IToolRegistry`), step 2 calls `speak`; verify both tool dispatches in log.
7. **Reached-end**: re-run `workflow_execute` on a completed workflow → `Success:false` "workflow complete".
8. **Separation**: Victoria's tasks are in `victoria_tasks`, NOT in `docs/agents/tasks/` (PM tickets). Confirm no PM ticket file was created by her.
9. **Regression**: E1, recall_memory, body tools still work.
10. Evidence in report: prompts, raw `tool_calls`, SQLite rows, workflow execution log, Pass/Fail. File ISSUE on failure.
