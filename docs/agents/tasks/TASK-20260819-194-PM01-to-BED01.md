# TASK-194: Honest browser Success + guidance (hours, no Playwright dep)

## Problem

Victoria reports multi-step web work as done after one or two tools. `browser_navigate`
can return Success after **launching Firefox**, not after load. Guidance still steers
**screenshot-first for Login**. AT-SPI fail + PNG is treated like a good snapshot.

## Root cause (TT-193 / PROP)

| Gap | Where |
| --- | --- |
| Navigate Success = process spawn | `GuestVmBrowserBridge` / browser tools |
| Screenshot-first Login | `ComputerUseGuidance` |
| Snapshot Success on AT-SPI fail → PNG | `GuestVmBrowserBridge.SnapshotAsync` / ForceTool companions |
| Chat "done" = tool Success | Tool-loop / guidance — no `goal_complete` postcondition |

## Solution (do now — before Playwright)

1. **`browser_navigate` Success** only after URL/load wait (or explicit timeout with Success:false). Never Success solely for Firefox/Chrome spawn.
2. **Split semantics** in tool result payload (or Content contract):
   - `action_ok` — this tool call worked
   - `goal_complete` — page postcondition met (URL/title/locator) — default false unless asserted
3. **Guidance:** remove screenshot-as-primary-locator for labeled web UI / Login. Prefer role/name click/fill (Playwright coming in BED-195; until then prefer `browser_click_text` / fill over `desktop_screenshot`→pixel).
4. **Do not** treat AT-SPI-fail + PNG as successful `browser_snapshot` for ForceTool exclusivity without saying `degraded=true` and `locator=pixel`.
5. Align ComputerUse preamble: stop contradicting "Kurt's Windows desktop" vs scoped VM.
6. Unit tests for navigate honesty + intent/guidance strings.

## Do not

- Do not implement Playwright in this ticket (BED-195).
- Do not attach to Kurt's Chrome.
- Do not weaken AllowComputerControl.
