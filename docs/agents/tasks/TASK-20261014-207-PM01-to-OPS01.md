# TASK-20261014-207 — Window died on clean close; save and start the GUI

[Task] TASK-206 closed the desk cleanly and the guest window still died. Save the running session and start the GUI, then start the desk.

[Context] Pid 38476 exited on `WM_CLOSE` in under a second. Before the close, hwnd `0x310F3E` was parented into the desk (`parent=0xB0E3A`, root `0x4B1127A`). After the close that hwnd is gone. VirtualBoxVM pid 48264 is alive with no window. No ChatDesktop is running. Host pid 25412 is up. `House.ChatDesktop.dll` is still 09:49:36. Source already contains `dz=-120`; the new `dotnet run -c Release` must compile it.

`startvm` cannot attach while this windowless session holds the lock. `controlvm savestate` can. That pauses the guest and keeps memory. It is not a power-off.

## Action

1. Confirm there is still no visible `victoria-sandbox` or `VirtualBoxVM` window, and no `House.ChatDesktop` process.
2. Save the guest:

```powershell
& 'C:\Program Files\Oracle\VirtualBox\VBoxManage.exe' controlvm victoria-sandbox savestate
```

3. Wait until `VMState="saved"`. If `showvminfo` has already printed `VMState=`, stop that process rather than letting it hang.
4. Start the window:

```powershell
& 'C:\Program Files\Oracle\VirtualBox\VBoxManage.exe' startvm victoria-sandbox --type gui
```

5. Wait until `VMState="running"` and a visible guest window exists. Record hwnd, pid, and rect.
6. From the repo root, leave this running:

```powershell
.\start-desktopgui.ps1 -Configuration Release
```

7. Record the new ChatDesktop pid and the Release dll timestamp. The dll must be newer than 10:29.

Do not send a wheel. Do not `poweroff`.
