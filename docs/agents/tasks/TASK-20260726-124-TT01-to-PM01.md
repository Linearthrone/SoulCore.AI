# TASK-124: Ticket out Victoria agent loop (tool-calling + tool registry)

## Ask

User wants Victoria to have **all the tools she had in the prior version** —
the ones we made (HouseVictoria MCP) and the ones from Hermes. Today she has
zero LLM-driven tools; 5 body verbs are keyword side-effects. The full
engineering plan + tool inventory is in the proposal above.

## Bottom line

SoulCore's inference is single-shot text → string. No `tools`, no `tool_calls`,
no tool-loop. Victoria cannot decide to act. LLMOD had ~60 LLM-callable tools
through a Hermes tool-loop with MCP servers. The proposal restores that agency.

## What's in the proposal

- **Agent loop**: `/api/chat` with `tools` → model emits `tool_calls` → Host
  executes → result fed back → model continues (both Ollama native and Hermes
  paths).
- **Tool registry**: `IToolRegistry` + `ToolDefinition` + `ToolResult` in C#;
  tools as DI singletons; Host builds `tools[]` per turn.
- **Full tool inventory** (categorized, with LLMOD source paths): body/editor,
  memory/banks, task/workflow, desktop/browser, trading/MT4, system, filesystem.
- **6 waves**: core agency → environment → self/system → desktop/browser →
  trading → task/workflow.
- **Security gates**: session opt-in (desktop), per-trade confirmation (MT4),
  whitelisted filesystem roots.
- **Model risk**: `gemma4` may not support tool-calling; `qwen2.5:14b`
  recommended (very good tool-calling, fits 16 GB card).
