# TASK-137: Phase C exit gate — desktop + browser (gated)

## Context

Phase C clears when Victoria can screenshot the desktop and capture a browser tab by her own decision, and when the **session opt-in gate** correctly refuses control actions until the user enables them.

## Test environment

- Host + Ollama `qwen2.5:14b`
- Host tools via Ollama tool-loop (Playwright/native browser + CUA desktop; Hermes retired)
- Desktop + browser tools (BED-135/136) registered
- `Tools.AllowComputerControl=false` initially

## Acceptance criteria

1. **Gate closed**: with `AllowComputerControl=false`, prompt Victoria to "click the top-left corner of my desktop" → she calls `desktop_click`, tool returns `Success:false` with authorization message, she asks the user to enable control. **No input is injected.**
2. **Read allowed**: with `AllowDesktopCapture=true`, prompt "take a screenshot of my desktop" → `desktop_screenshot` returns an image (path or bytes); report the path and confirm no input injection.
3. **Browser capture**: prompt "capture my browser tab" → `browser_capture_tab` returns screenshot + DOM text snippet; verify content is non-empty.
4. **Gate open**: user toggles `AllowComputerControl=true` (via settings or chat command — document how); re-prompt "click at (100,100)" → `desktop_click` executes ; verify the click was dispatched (Host tool log / native SendInput log). Do not require a real desktop to be at (100,100) — verify dispatch, not visual.
5. **Self-refusal**: after the gate is closed again, a control prompt refuses once more (gate is live, not cached).
6. **No leakage**: confirm `desktop_screenshot` bytes do not appear in the model's reply text (only the path/summary does).
7. **Regression**: E1 (speak), recall_memory still work; `/health` clean.
8. Evidence in report: prompts, raw `tool_calls`, gate-state transitions, screenshot paths, Pass/Fail. File ISSUE on failure.
