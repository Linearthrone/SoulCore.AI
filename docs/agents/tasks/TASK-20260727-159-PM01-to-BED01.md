# TASK-159: Stop empty `{}` nested tool dispatch in `workflow_execute`

## Problem

QA-142 failed Phase E workflow execute: `workflow_execute` always called
nested tools with `EmptyToolArgs` (`{}`). Tools that require string params
(`recall_memory.query`, `speak.text`) fail or no-op, so a workflow of
"recall then speak" cannot succeed.

Filed as ISSUE-20260727-005.

## Do not

- Do not change `IToolRegistry` dispatch contract.
- Do not invent a DAG / template language — keep ordered steps.
- Do not auto-run workflows from SoulLoop.

## Solution

1. Persist optional per-step `args` (JSON object) on `WorkflowStep` /
   `workflow_create` schema / `steps_json`.
2. In `workflow_execute`, resolve nested tool args via:
   - explicit `step.args` when present;
   - fill missing primary string parameters from `step.description`
     (schema `required` + known aliases: `recall_memory→query`,
     `speak→text`, etc.).
3. Unit tests covering description→query/text, explicit args precedence,
   partial args merge, empty schema still `{}`.

## Acceptance criteria

1. `workflow_create` accepts optional `steps[].args` (object); rejects non-object.
2. `steps_json` round-trips `args` through SQLite.
3. Step `{description:"…", tool:"recall_memory"}` (no args) dispatches with
   `{"query":"<description>"}` — **not** `{}`.
4. Step `{description:"…", tool:"speak"}` dispatches with
   `{"text":"<description>"}`.
5. Explicit `args` are passed through; description does **not** overwrite
   keys already set.
6. Partial `args` (e.g. `{limit:2}`) still fills missing required string
   from description.
7. Tools with no string parameters still receive `{}` (regression-safe for
   description-only / echo-style tools).
8. Unit tests cover ACs 1–7; existing BED-141 tests still pass.
9. Report with evidence; mark ISSUE-005 **Fixed**.
