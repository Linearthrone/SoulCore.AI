# TASK-20261014-203 — Save state, then start the GUI

[Task] TASK-202 could not open a second frontend. The running session has no window. Save the guest and start the GUI again.

[Context] `startvm --type gui` returned `VBOX_E_INVALID_OBJECT_STATE` (already locked). `--type separate` returned the same code (state incompatible). VirtualBoxVM pids 40864, 44188, 44216 have no window. `VMState` is still `running` since 09:28. ChatDesktop pid 15392 is up. Host pid 25412 stays up.

`controlvm savestate` talks to the existing session. `startvm` cannot, because that session already holds the lock. A save pauses the guest and keeps memory. It is not a power-off.

## Action

1. Close House.ChatDesktop so its shared console lock is released. Post a close to pid 15392 and wait up to 20 seconds. If it is still running, stop that process and its `dotnet run` parent. Do not stop Host. Do not stop VirtualBoxVM yet.
2. Save the guest:

```powershell
& 'C:\Program Files\Oracle\VirtualBox\VBoxManage.exe' controlvm victoria-sandbox savestate
```

3. Wait until `VMState="saved"`. If `showvminfo` has already printed `VMState=`, stop that process rather than letting it hang.
4. Start the window:

```powershell
& 'C:\Program Files\Oracle\VirtualBox\VBoxManage.exe' startvm victoria-sandbox --type gui
```

5. Wait until `VMState="running"` and a visible window titled `victoria-sandbox` or `VirtualBoxVM` exists. Record hwnd, pid, and rect.
6. Start the desk again and leave it running:

```powershell
.\start-desktopgui.ps1 -Configuration Release
```

Do not send a wheel.

## Do not

- `poweroff`, `reset`, or `acpipowerbutton`
- Stop SoulCore.Host
- Claim the wheel works
