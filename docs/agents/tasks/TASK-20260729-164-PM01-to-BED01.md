# TASK-164: PreferHermes Avenue B (Ollama tool-loop + Hermes MCP-only)

## Problem

hermes-agent 0.18.2 advertises `tool_execution: server` and does **not** return client-visible OpenAI `message.tool_calls` for Host ITool dispatch. PreferHermes turns that call Hermes `CompleteWithToolsAsync` / `tools[]` let the live server agent bypass SoulCore ITools (ISSUE-002).

## Solution (Avenue B)

1. PreferHermes tool-loop runs on **Ollama** (`IInferenceClient.CompleteWithToolsAsync`).
2. Hermes is **MCP-only** via `CallMcpToolAsync` (hermes backends inside SoulCore ITools).
3. PreferHermes turns must **never** send `tools[]` through Hermes `CompleteWithToolsAsync`.
4. Keep fail-fast / unavailable when Hermes MCP gateway/key is down (`EnsureMcpReadyAsync` preflight).
5. Do not break PreferHermes=false Ollama path; do not patch Hermes Python.

## Acceptance criteria

1. PreferHermes=true → Ollama `CompleteWithToolsAsync` called; Hermes `CompleteWithToolsAsync` **not** called.
2. PreferHermes=true + Hermes MCP down → fail-fast (`chat.model_down` / unavailable); Ollama tool-loop not started.
3. PreferHermes=false → Ollama primary unchanged; Hermes secondary failover still allowed.
4. hermes-backend tools still use `CallMcpToolAsync` only.
5. ISSUE-002 marked Fixed with evidence.
6. Build 0 warnings + Protocol.Tests Pass for PreferHermes / Hermes tool-loop filters.
