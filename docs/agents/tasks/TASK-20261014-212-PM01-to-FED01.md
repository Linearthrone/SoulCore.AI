# TASK-20261014-212 — Page Up must be queued

[Task] A wheel on her screen still does not move the guest page. Make the Page Up / Page Down tap a real key the guest can see, and stop logging `sent` when the keyboard queue did not take it.

[Context] TASK-211: Release pid 38920, Firefox on the Ubuntu desktop open to the Maestro lesson "The box model." One wheel-away detent. Startup log: `her-screen wheel notches=1 key=pageup sent`. The lesson did not move (shift 0). Before and after frames in `tmpcode/qa-211/` are the same page.

`VictoriaVmPointer.SendScancodes` calls `IKeyboard.putScancode` once per byte and ignores the count VirtualBox returns. `DeliverWheelKeys` then logs `sent`. Make and break go out in the same burst: `E0 49 E0 C9` with no gap.

The Host path that does reach this Wayland Firefox is `VBoxManage controlvm keyboardputscancode`, which is one `IKeyboard.putScancodes` array. Before each tap it releases stuck modifiers (`VboxConsoleKeyboard` modifier-release prefix: `AA B6 9D B8 E0 DB`). Page Up there is the same bytes: extended `49` / `51`.

Do not go back to mouse `dz`. Do not change `desktop_scroll` or xdotool. Do not edit Host keyboard code. Do not stop pid 38920. Do not `startvm`, `controlvm`, `savestate`, or `poweroff`. Avalonia stays on 11.3.x.

## Amendment (operator, 11:13)

Maestro only scrolls when the pointer is in the center vertical section of the window. The lesson column is that band. A Page Up tap with the pointer elsewhere does not move the page.

Before the key tap, seat the guest pointer at the center of the guest framebuffer (`width / 2`, `height / 2`) with one `PutMouseEventAbsolute` and `dz=0`. Then one left click there (press, then release) so that column is focused. Then the Page Up or Page Down tap. Do not send a mouse-wheel `dz`. Do not park the cursor outside the embed for this path.

## Requirements

1. One wheel detent is still one Page Up (positive) or Page Down (negative) tap. Bytes stay `E0 49` / `E0 C9` and `E0 51` / `E0 D1`.
2. Send each tap as one `putScancodes` array for the make, then one array for the break. Wait about 40 ms between make and break. If `putScancodes` is missing on that COM object, `putScancode` per byte is allowed only when each call's stored count is added up.
3. Before the tap, send one modifier-release prefix, the same six bytes as the Host: `AA B6 9D B8 E0 DB`. Once per wheel, not once per notch.
4. Log `sent` only when the stored count for the prefix, the make, and the break equals the number of bytes handed over. The line must include the seat and that count, for example `her-screen wheel notches=1 key=pageup seat=640,400 stored=10 sent`. A short count is not `sent`. Log `stored=` and `COM error:` on that same line.
5. Before the modifier-release and the Page key, seat the guest pointer at the center of the guest framebuffer (`width / 2`, `height / 2`) with one `PutMouseEventAbsolute` and `dz=0`. Use the live guest size when it is known, otherwise `VictoriaBrowserCoordMap.DefaultGuestWidth` / `DefaultGuestHeight` (1280×800). Then one left click at that same point (button down, then button up). Then the prefix, the make, about 40 ms, and the break. Do not send a mouse-wheel `dz`. Do not park the Windows cursor outside the embed for this path.
