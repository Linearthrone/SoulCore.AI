# TASK-133: System + filesystem tools — `list_tools`, `system_info`, `read_file`, `write_file`, `list_dir`

## Problem

Victoria has no self-discovery (cannot ask "what tools do I have?"), no system introspection, and no file access. LLMOD had `list_house_victoria_tools`, `system_info`, and the `house_victoria_data` MCP for scoped filesystem. Restore the SoulCore-native versions.

## Do not

- Do not change `IToolRegistry` (BED-125).
- Do not implement desktop/browser/trading tools (BED-135/136/138).
- Do not give unrestricted filesystem access — **whitelisted roots only** (per proposal security gate).

## Solution

### `list_tools` (self-discovery)

Returns the list of registered tools + their descriptions. The model can ask "what can I do?".

```json
{ "name": "list_tools", "description": "List all tools available to you with their descriptions.", "parameters": { "type":"object","properties":{} } }
```

Returns: `ToolResult(Success, Content: "available tools:\n - recall_memory: ...\n - speak: ...\n ...", Data: [names])`.

### `system_info`

Returns host build, model, uptime, memory count, SoulLoop status — same shape as `/health` summary.

```json
{ "name": "system_info", "description": "Get SoulCore system status (model, uptime, memory, safety).", "parameters":{ "type":"object","properties":{} } }
```

### Filesystem tools (scoped)

Whitelisted roots only. Default roots (configurable in `appsettings` → `Tools.FilesystemRoots`):
- `%LOCALAPPDATA%/SoulCore/memory/` (read-only by default)
- `SoulCore/scripts/qa-*/` (read/write — QA artifacts)
- A user-configurable scratch dir (e.g. `SoulCore/scratch/`)

Reject any path that escapes the whitelist (resolve + canonicalize + check prefix).

```json
{ "name": "read_file", "description": "Read a text file (whitelisted roots only).", "parameters":{ "type":"object","properties":{ "path":{"type":"string"} }, "required":["path"] } }
{ "name": "write_file", "description": "Write a text file (whitelisted roots only).", "parameters":{ "type":"object","properties":{ "path":{"type":"string"},"content":{"type":"string"} }, "required":["path","content"] } }
{ "name": "list_dir", "description": "List files in a directory (whitelisted roots only).", "parameters":{ "type":"object","properties":{ "path":{"type":"string"} }, "required":["path"] } }
```

Return `ToolResult(Success:false, Content:"path not in whitelisted roots: ...")` on escape attempt — do not throw, do not log the rejected content at Info.

## Acceptance criteria

1. All five tools implement `ITool`, register in DI, appear in registry.
2. `list_tools` returns names + descriptions of all registered tools (verified against a 2-tool mock registry).
3. `system_info` returns model, uptime, memory count, SoulLoop status (no secrets).
4. Filesystem tools enforce whitelist: `../escape`, absolute paths outside roots, symlinks pointing out — all rejected with `Success:false`.
5. `write_file` only allowed under `FilesystemWriteRoots` (subset of read roots).
6. Config: `Tools.FilesystemRoots` in appsettings with sensible defaults; empty list = filesystem tools disabled (return `Success:false, "filesystem tools disabled"`).
7. Unit tests: whitelist escape, list_tools, system_info, read/write/list round trip inside a root.
8. Report: file paths, default roots, escape-test evidence, unit test results.
