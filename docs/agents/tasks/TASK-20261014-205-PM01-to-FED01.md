# TASK-20261014-205 — dz of 1 does not scroll this guest

[Task] The inject path is doing what TASK-199 asked. The Ubuntu guest does not move for `dz=-1`.

## What QA measured

Release pid 38476. `HerScreenInput` hwnd `0x3E0C6E`. One `WM_MOUSEWHEEL` +120. After frame at 436 ms.

- Log: `2026-10-14 10:18:39.736 her-screen wheel notches=1 point=602,295 sent`
- Cursor inside the embed at 13 ms, 151 ms, and 308 ms, including the seat `(6360,485)`
- Guest best shift **0** (body crop 0)
- Chat shift **0**

`InjectPointer` already sends one `PutMouseEventAbsolute(ax, ay, dz, 0, 0)` with the cursor seated inside the embed. `GuestWheelDz(1)` is `-1`. COM returned. The lesson did not move. Cursor placement and the stale-session theory are not this failure.

## Root cause

`VictoriaVmPointerPlan.GuestWheelDz` maps one Windows detent to `dz=-1`. This guest's absolute mouse ignores a wheel amount of 1. A Windows detent is `WHEEL_DELTA` 120. The startup line hides that, because it logs `notches=1` and not the `dz` that was sent.

## Solution

1. One notch sent to `IMouse` is `dz = -notches * 120`. Positive Windows-away still scrolls content up, so the sign stays negative. Do not send `-1`.
2. Keep the single `PutMouseEventAbsolute` call, the in-embed cursor seat, reconnect, and button park-outside.
3. The startup line must include the `dz` value, for example `notches=1 dz=-120 point=602,295 sent`.
4. Update the wheel tests that currently expect `GuestWheelDz(1) == -1`.
