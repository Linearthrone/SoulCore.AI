# TASK-091 — Wire safety libs into active paths (DriftWatcher + SpendMeter)

## Context

BED-080 built the safety library layer (CharterService, DriftWatcher, SpendMeter) and
BED-082 wired them into Host DI. However, these services are currently **passive** —
they are registered but never called in the live code paths.

The north-star plan (§2.5 Safety Boundaries) requires:
- DriftWatcher: "Periodically compare current values, goals, and emotional patterns
  to baseline. If I shift significantly, report before acting on it."
- SpendMeter: "Do not burn all GPU, CPU, disk, or money." (Resource guard)

## Deliverable

### 1. DriftWatcher → SoulLoop tick

In `SoulLoopScaffold.TickAsync`, after computing the want:
- Call `_driftWatcher.RecordDrift(label, fields, want)` with the current emotion label,
  emotion fields (valence/arousal/dominance), and the generated want string.
- If `RecordDrift` returns a status indicating drift is active (unacknowledged drift
  beyond the SLO window), log a warning and include a `drift_alert` field in the
  `loop.want` frame payload.
- Inject `DriftWatcher` via constructor (it's already in DI).

### 2. SpendMeter → Inference path

In `ChatWebSocketHandler.CompleteChatAsync`, after each successful inference call:
- Call `_spendMeter.RecordUsage(inputTokens, outputTokens)` with the token counts
  from the inference response (Ollama returns `prompt_eval_count` and `eval_count`;
  Hermes returns `usage.prompt_tokens` and `usage.completion_tokens`).
- Wrap in try/catch (never break chat if spend recording fails).
- Inject `SpendMeter` via constructor (it's already in DI).
- Note: If token counts aren't available from the response, use estimated counts
  (chars/4 as rough token estimate).

### 3. DriftWatcher → /health endpoint

In the health endpoint, add a `safety.drift` field showing:
- `activeDriftCount`: number of unacknowledged drifts
- `oldestDriftMinutes`: minutes since oldest unacknowledged drift

## Acceptance criteria

- [ ] `SoulLoopScaffold.TickAsync` calls `DriftWatcher.RecordDrift` each tick
- [ ] `ChatWebSocketHandler.CompleteChatAsync` calls `SpendMeter.RecordUsage` after inference
- [ ] `/health` includes safety drift summary
- [ ] All 62 existing tests pass
- [ ] Build: 0 errors, 0 warnings (excluding file-lock MSB302x)
- [ ] No changes to public interfaces (internal wiring only)
- [ ] Report to `docs/agents/reports/TASK-20260723-091-BED01-to-PM01.md`

## Constraints

- Do NOT restart the Host (OPS will handle that)
- Do NOT change `appsettings.json` (safety config already set)
- Keep all safety calls in try/catch — safety lib failures must never break chat or loop
- DriftWatcher is report-only (no blocking, no soft-block yet — that's a future gate)
