# TASK-100: Wire episodic recall + charter identity anchors into chat context

## Context

The north-star plan (Avenue A, Phase 1) requires that Victoria's chat responses be informed by her memory and identity. Currently, `HandleChatSendAsync` in `SoulCore.Host/Ws/ChatWebSocketHandler.cs` passes only the **emotion preamble** to the inference client (`CompleteChatAsync`). Episodic memories and charter identity anchors are NOT included in the chat context — so Victoria responds "stateless" despite having memories and charter anchors in the SQLite DB.

This is the single biggest gap between the current MVP and the north-star "continuous self" vision.

## Acceptance criteria

1. **`ChatWebSocketHandler` constructor** accepts `ICharter` (already in DI as `CharterService` singleton) in addition to existing dependencies.

2. **`HandleChatSendAsync`** recalls recent episodic memories (via `_memory.RecallRecentAsync`) AND gets charter identity anchors (via `_charter.GetAnchorsByKindAsync("identity")`) BEFORE calling `CompleteChatAsync`.

3. **A new `BuildContextPreamble` method** combines the existing emotion preamble with:
   - A `[Memory]` section: the N most recent non-quarantined episodic memories (N = 5, matching `SoulLoopOptions.EpisodicRecallLimit` default or a new `ChatContextMemoryLimit` option)
   - A `[Identity]` section: the charter identity anchor body texts (joined by newline)
   - The existing emotion preamble (unchanged)
   The order should be: `[Identity]` → `[Memory]` → `[SoulCore emotion]` (identity first, memory second, emotion last).

4. **`CompleteChatAsync` signature** changes from `(text, emotionPreamble, ct)` to `(text, contextPreamble, ct)` — or the emotion preamble is replaced by the combined context preamble. The `IInferenceClient.CompleteAsync` and `IHermesClient.ChatAsync` both already accept `systemPreamble`.

5. **Token budget**: The context preamble is truncated to a reasonable limit (e.g., 2000 chars total) to avoid blowing the model's context window. If memory or identity exceeds the limit, truncate the oldest memories first.

6. **Error handling**: If charter or memory recall fails, chat continues with whatever is available (graceful degradation — same pattern as emotion read). Log at Debug level.

7. **Episodic write after chat** remains unchanged — the existing `WriteEpisodicAsync(episode, "chat", ct)` call stays as-is.

8. **No new dependencies** — uses existing `ICharter`, `IMemoryStore`, `EmotionInfluencePrompt`. No new NuGet packages.

9. **Build passes** — `dotnet build` of `SoulCore.sln` succeeds with zero errors.

10. **Tests pass** — existing `SoulCore.Protocol.Tests` project passes. If the constructor change breaks test setup, update test constructors to pass a `CharterService` or `ICharter` stub.

## Implementation notes

- `ICharter` is already wired in `Program.cs` DI: `builder.Services.AddSingleton<ICharter>(sp => sp.GetRequiredService<CharterService>());`
- `IMemoryStore` is already injected into `ChatWebSocketHandler`.
- `RecallRecentAsync(limit)` returns `IReadOnlyList<string>` of content texts, excluding quarantined rows, ordered by `occurred_at DESC`.
- `ICharter.GetAnchorsByKindAsync("identity")` returns `IReadOnlyList<string>` of anchor body texts, ordered by priority.
- The `EmotionInfluencePrompt.BuildPreamble` output should be the LAST section of the combined preamble (emotion is closest to the model's attention).
- Keep the combined preamble deterministic (same inputs → same string) — do not inject timestamps or random data.
