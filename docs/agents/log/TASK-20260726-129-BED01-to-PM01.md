### Known qwen2.5 tool-call flakiness (IMPORTANT — read before BED-126)

On the **first** smoke attempt (with a softer system prompt), the model did
**not** emit `tool_calls` — it returned a Thai-language text reply containing
the tool call as **bare JSON in `content`** (e.g.
`{"name": "echo", "arguments": {"text": "hello"}}`). This is a **known
Ollama issue with the qwen2.5 model family**, tracked in:

- ollama/ollama #13968 — "Qwen2.5:14b output json tool call leak - INCORRECT
  TOOL CALL" (exactly this symptom: bare JSON in `content`, random Chinese
  chars, "only works occasionally").
- ollama/ollama #12174 — `qwen2.5-coder:14b` emits `tool_calls: null` with
  `content: bare JSON`; `qwen3:8b` works through the same pipeline.
- NousResearch/hermes-agent #5867 — same; workaround is to parse the JSON
  from `content` as a fallback.

The root cause (confirmed by dumping `ollama show qwen2.5:14b --modelfile`):
the model's chat template instructs it to wrap tool calls in XML-like tags,
but the model frequently emits bare JSON without the tags, so Ollama's
parser doesn't promote it to the `tool_calls` field.

**With the stronger imperative system prompt used in the final smoke, all 3
runs produced proper structured `tool_calls`.** The smoke also includes a
content-embedded-JSON fallback parser (yellow "content-fallback" mode) so it
still reports PASS if the model leaks the call into `content`.

**Recommendation for BED-126 (Ollama tool-loop):** the tool-loop client MUST
(1) check `message.tool_calls` first, and (2) fall back to parsing
`message.content` as JSON matching `{"name": "...", "arguments": {...}}`
when `tool_calls` is null/empty. Without the fallback, the agent loop will
miss tool calls on the flaky runs. This is the single biggest technical
risk noted in the proposal — confirmed here empirically.

No Issue file was opened because the model DOES support tool-calling (3/3
structured passes with the right prompt); the flakiness is a known upstream
Ollama/template issue with a documented workaround, not a hard failure of
`qwen2.5:14b`. If BED-126 finds the flakiness unacceptable in production,
PM can re-decide (file an Issue then).
