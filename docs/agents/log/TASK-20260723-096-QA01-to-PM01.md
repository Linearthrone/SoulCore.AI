## Observations (not failures — for PM-01 awareness)

### Observation A: E1 speak has no Information-level log when UE is disconnected

The `ChatWebSocketHandler` emits dedicated `Unreal ... intent dispatched` log
lines for loco (line 393), animation (line 411), and look (line 431) — these
fire at Information level REGARDLESS of UE connectivity because they are
logged after the verb client call returns (not inside it). The speak verb,
however, is sent in the generic side-effect block (lines 367-374) WITHOUT a
dedicated intent log. When UE is connected, the verb client logs
`Unreal verb sent: soul=speak` at Information level (proven in TASK-093). When
UE is disconnected, the verb client logs `Unreal verb dropped (not connected):
speak` at Debug level, which is invisible at the default log level.

**Implication for PM-01:** This means E1 (speak) cannot be proven from the host
log alone when UE is down. The only proof available is `chat.done` (the chat
path completed, so the side-effect block was reached) and the absence of
exception logs. This is sufficient for "no regression" but is weaker evidence
than E7/E3/E8, which have dedicated intent logs. If a dedicated
`Unreal speak intent dispatched` Information log is desired for parity with
loco/animation/look, that would be a small future ticket (one LogInformation
line in the speak side-effect block of `ChatWebSocketHandler`).

This is NOT a BED-094 regression — the speak path was unchanged by Wave-17. The
behavior is identical to TASK-093's E1 test, which passed because UE was
connected there (so `soul=speak` logged at Information level).

### Observation B: NSFW-flash model produces profane content

During the E8 test ("look at me"), the Ollama NSFW-flash:Q4_K_M model
generated profanity in its reply ("I'm feeling pretty f***ed up right now").
This is the same known characteristic flagged in TASK-093 Observation B. It is
NOT a regression introduced by BED-094/095 — the look_at dispatch and charter
seed do not touch inference content. Out of scope for TASK-096.
