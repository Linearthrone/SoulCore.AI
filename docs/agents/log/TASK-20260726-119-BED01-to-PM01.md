# TASK-119 Report — `play_animation` JSON `payload.args.name` parse

## Result: PASS

Bridge now parses the animation name from Host JSON `payload.args.name` (with a
PlainArgs line-protocol fallback) for `play_animation`. Fix verified by a clean
C++ compile of the plugin. Montage/avatar assets may still be missing — as the
ticket states, **parse success is enough**, and the dispatch path already returns
`success:true` even when the avatar/montage is absent (stub ack).

## Root cause

`UHouseVictoriaBridgeBPLibrary::ParseWebSocketMessage` populates `PlainArgs`
**only** for plain line-protocol frames. For a JSON frame it sets
`bWasJson = true` and leaves `PlainArgs` **empty**:

```143:150:../OneDrive/Documents/Unreal Projects/MyProject/Plugins/HouseVictoriaBridge/Source/HouseVictoriaBridge/Private/HouseVictoriaBridgeBPLibrary.cpp
    OutMessage.bParsedOk = true;
    OutMessage.bWasJson = false;
    OutMessage.MessageType = TEXT("plain");
    OutMessage.PrimaryVerb = Parts[0];
    for (int32 i = 1; i < Parts.Num(); ++i)
    {
        OutMessage.PlainArgs.Add(Parts[i]);
    }
```

Any `play_animation` handler that read `PlainArgs` only therefore received an
empty name for the Host's JSON envelope and returned `success:false` — the same
class of bug as speak/BED-067 and set_emotion.

## Verbs / servers touched

Two handlers dispatch `play_animation` in the plugin. The **active** server is
`FHouseVictoriaBridgeServer` (created and started by the module in
`FHouseVictoriaBridgeModule::StartupModule` on the configured `WebSocketPort`).
`UHouseVictoriaSocketSubsystem` is a parallel handler for the same verb. Both are
now JSON-aware.

### 1. `FHouseVictoriaBridgeServer` (primary, module-started) — already correct + verified

`play_animation` uses `ParseAnimationName`, which reads JSON `payload.args.name`
when `bWasJson`, and falls back to the PlainArgs tail otherwise:

```381:411:../OneDrive/Documents/Unreal Projects/MyProject/Plugins/HouseVictoriaBridge/Source/HouseVictoriaBridge/Private/HouseVictoriaBridgeServer.cpp
bool FHouseVictoriaBridgeServer::ParseAnimationName(
    const FString& RawMessage,
    const FHouseVictoriaParsedMessage& Parsed,
    FString& OutName) const
{
    OutName.Reset();

    if (Parsed.bWasJson)
    {
        TSharedPtr<FJsonObject> Root;
        const TSharedRef<TJsonReader<>> Reader = TJsonReaderFactory<>::Create(RawMessage);
        if (FJsonSerializer::Deserialize(Reader, Root) && Root.IsValid())
        {
            const TSharedPtr<FJsonObject>* PayloadPtr = nullptr;
            const TSharedPtr<FJsonObject>* ArgsPtr = nullptr;
            if (Root->TryGetObjectField(TEXT("payload"), PayloadPtr) && PayloadPtr->IsValid()
                && (*PayloadPtr)->TryGetObjectField(TEXT("args"), ArgsPtr) && ArgsPtr->IsValid())
            {
                FString Name;
                if ((*ArgsPtr)->TryGetStringField(TEXT("name"), Name) && !Name.TrimStartAndEnd().IsEmpty())
                {
                    OutName = Name.TrimStartAndEnd();
                    return true;
                }
            }
        }
        return false;
    }

    return ParseStringTail(Parsed.PlainArgs, OutName);
}
```

### 2. `UHouseVictoriaSocketSubsystem` (parallel handler) — fixed this ticket

Previously `play_animation` used `ParseStringFromArgs` (PlainArgs-only), so a JSON
frame produced an empty name. Added `ParseAnimationNameFromArgs` (JSON
`payload.args.name` + PlainArgs fallback), mirroring the working
`ParseEmotionFromArgs` pattern, and switched the `play_animation` branch to use it:

- `HouseVictoriaSocketSubsystem.cpp` — `play_animation` branch now calls
  `ParseAnimationNameFromArgs(RawMessage, Parsed, AnimName)`.
- New helper reads JSON `payload.args.name`, trims, and falls back to
  `ParseStringFromArgs` for the plain path.
