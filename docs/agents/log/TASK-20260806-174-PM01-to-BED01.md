# TASK-174: Desktop navigate & execute without Hermes

## Problem (user-reported)

Kurt: screenshot tool works; asking to **open a Google Chrome window on the desktop** still steers Victoria toward **Hermes**. She needs to navigate and execute on the local Windows machine via SoulCore native/`cua` backends.

## Root cause (verified)

| Gap | Evidence |
| --- | --- |
| **No launch tool** | `IDesktopControlBackend` has screenshot/click/drag/type/key/list/focus only — no `OpenApp` / shell. `focus_desktop_window` only activates **already-running** titles. |
| **ForceTool wrong for “open Chrome”** | `DesktopToolIntent.UseComputer` matches `open … chrome` → ForceTool **`list_desktop_windows`** (`ComputerUseGuidance.cs`), not a launch. |
| **Guidance omits launch** | `[Computer]` block: list → click → drag → type. Never says open/start app. Never forbids inventing Hermes `terminal` / `computer_use` / `browser_navigate` for local launch. |
| **Hermes browser lure** | `BrowserBackend=hermes`; browser_* always MCP. Model may invent Hermes after list finds no Chrome. PreferHermes does **not** flip `DesktopBackend` (native screenshot is correct). |
| **Navigate gaps vs LLMOD** | No wheel/scroll; `desktop_key` is single-key (no `Ctrl+L` / chords); no double-click. |

`DesktopBackend=native` in `appsettings.json` is fine — do **not** switch desktop to Hermes.

## Solution

### A. `desktop_open_app` (required)

1. Extend `IDesktopControlBackend` with `OpenAppAsync(string app, string? args, CancellationToken)`.
2. **Native:** allowlisted launch via `Process.Start` / `ShellExecute` (Windows). Suggested allowlist keys (aliases → executable or URI):
   - `chrome` → Google Chrome (`chrome.exe` / common install paths / `start chrome`)
   - `msedge` / `edge`
   - `firefox` (if found; else clear Success:false)
   - `notepad`, `explorer` / `file_explorer`
   - `cmd`, `powershell` (optional; document)
   - Absolute path under Program Files only if you want escape hatch — prefer named allowlist first
3. **Cua:** launch via same native Process.Start (cua-driver does not need to own process create) unless driver already has a launch verb.
4. **Hermes backend:** optional MCP passthrough if a matching tool exists; otherwise Success:false with “use native/cua DesktopBackend”.
5. New `DesktopOpenAppTool` (`desktop_open_app`):
   - Params: `app` (string, required), `args` (optional string, e.g. URL `https://…`)
   - Gate: **`AllowComputerControl`** (launch is execute, not capture)
   - Register in `Program.cs`; update registry tests (7 → 8 desktop tools)
6. If `args` looks like a URL and `app` is a browser alias, pass URL to Chrome/Edge so “open Chrome to google.com” works in one call.

### B. Intent + guidance (required)

1. `DesktopToolIntent`: add `Kind.OpenApp` → ForceTool `desktop_open_app`.
2. Match phrases like `open … chrome|edge|google chrome|notepad|file explorer|browser` **before** generic UseComputer→list.
3. Update `ComputerUseGuidance.Block`:
   - Preferred flow: **open_app if not running** → list/focus → screenshot as needed → click/drag → type/key → verify
   - Explicit: for local desktop launch/control use SoulCore `desktop_*` only; **do not** invent Hermes `terminal`, `process`, `computer_use`, or `browser_navigate` when `DesktopBackend` is native/cua
4. Expand `ExplicitTool` regex to include `desktop_open_app`, `desktop_scroll` (if added), etc.
5. Tests: `"open a Google Chrome window on my desktop"` → ForceTool `desktop_open_app` (not `list_desktop_windows`).

### C. Navigate completeness (required for “navigate and execute”)

Implement on native (+ cua passthrough where applicable):

| Capability | Shape |
| --- | --- |
| **Scroll** | `desktop_scroll` — `x`, `y`, `deltaY` (and optional `deltaX`); wheel at point |
| **Key chords** | Extend `desktop_key` (or `keys` array / `modifiers`) to support `Ctrl+L`, `Alt+Tab`, `Ctrl+T`, `Enter`, etc. Keep backward compatible with single key |
| **Double-click** | `desktop_click` optional `clicks: 2` **or** dedicated `desktop_double_click` — pick one; document |

### D. Do not

- Do not set `DesktopBackend=hermes` or require Hermes for this path
- Do not add unbounded shell/`cmd /c` without allowlist
- Do not weaken `AllowComputerControl` (launch + click/type stay gated)
- Do not change MT4 / PreferHermes Avenue B contracts
- Do not implement full native browser DOM stack — open browser + desktop_* is enough for Kurt’s ask
