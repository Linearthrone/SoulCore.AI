# TASK-146: Ticket out phone companion port (text-chat + notifications)

## Ask

User wants the phone companion app ported from LLMOD to SoulCore so they can
chat with Victoria from their phone and **get notifications** (ding + lock-screen
notification) when she messages them while the app is backgrounded. Victoria is
becoming her own person and will want to reach out about things she's thinking
about, doing, or needs approved. The full engineering plan is in the proposal
above.

## Bottom line

LLMOD had an Android Kotlin companion (`AndroidRemoteCompanion/`) that talked
to `HouseVictoria.App :17890` over HTTP. SoulCore replaced that host with
`SoulCore.Host :7700` (WS). The phone app was left behind. The desktop
companion (`House.ChatDesktop`) already has WS chat + notifications; the phone
needs the same.

**No hard code blockers for text-chat.** The only gating item is a remote
access path (loopback bind blocks a phone — needs Tailscale serve or a SEC
reviewed LAN bind).

## What's in the proposal

- **Phase 0 (fast-tracked):** fork LLMOD Kotlin shell, swap HTTP client for
  OkHttp WS client to `SoulCore.Host :7700/ws`, implement `chat.send` +
  `chat.delta`/`chat.done` streaming.
- **Notifications (added to scope per user):** Android foreground service for
  background WS persistence, local notification channel on `chat.done` when
  backgrounded, user-configurable custom sound + vibration toggle, tap opens
  chat. Mirrors the desktop `NotificationService` design.
- **Auth + remote:** Bearer/X-Api-Key token in Android Keystore; Tailscale
  serve recommended (no LAN bind); SEC gate on any non-loopback bind.
- **Phase 1 (follow-on):** audio (STT/TTS) — requires new SoulCore STT infra.
- **Phase 2 (later):** image/file transfer, emotion strip, quiet hours, widget.

## Decisions PM should surface to user before Phase 0 starts

1. **Android only or iOS too?** LLMOD was Android-only. Recommend Android
   first, iOS follow-on.
2. **Remote access path** — Tailscale (recommended, no LAN bind, no SEC
   review) vs. LAN bind (needs SEC-01 sign-off)? Recommend Tailscale.
3. **Phase 0 scope** — text chat + notifications only, or also include
   emotion snapshot strip? Recommend text + notifications only for speed.

## Fast-track rationale

- No hard blockers — WS protocol already on Host.
- Phone is the natural channel for Victoria reaching out (user isn't always
  at the desk).
- Desktop companion already proved the WS chat + notification pattern; phone
  mirrors it.
- Audio (Phase 1) is the expensive part and can follow.
