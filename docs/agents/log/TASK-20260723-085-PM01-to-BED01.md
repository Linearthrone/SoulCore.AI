# TASK-085 — BED-01 — Add token generation limits to inference clients

## Context

QA-084 E2E gates found E1 (speak) and E3 (loco) FAIL due to inference timeouts. Investigation reveals the root cause: Ollama generates 2919+ tokens at ~120 t/s but never stops because the `OllamaGenerateRequest` has no `num_predict` / `max_tokens` field. The model generates endlessly until the HttpClient timeout kills it.

ISSUE-002 is a P1 hard-stop. SoulLoop cannot be enabled until E3 passes.

## Scope

### F1: Add MaxTokens to InferenceOptions

- Add `int MaxTokens { get; set; } = 256` to `InferenceOptions.cs` (default 256 tokens — enough for a chat response, short enough to complete in ~2-3s at 120 t/s).
- Add `"MaxTokens": 256` to the Inference section in `appsettings.json` and `appsettings.Example.json`.

### F2: Add num_predict to Ollama request

- Add an `options` field to `OllamaGenerateRequest` containing `num_predict`.
- Pass `MaxTokens` from `InferenceOptions` as `options.num_predict` in the request payload.
- This tells Ollama to stop generating after N tokens.

### F3: Add max_tokens to Hermes request

- Add `max_tokens` field to the Hermes chat completions request payload.
- Pass `MaxTokens` from `HermesOptions` (or reuse `InferenceOptions.MaxTokens` if Hermes doesn't have its own).
- This tells Hermes to stop generating after N tokens.

### F4: Add MaxTokens to HermesOptions (if not present)

- Add `int MaxTokens { get; set; } = 256` to `HermesOptions.cs` if it doesn't have one.
- Add to `appsettings.json` Hermes section.

### F5: Build + verify

- `dotnet build SoulCore/SoulCore.sln -c Debug` → 0 Warning(s) 0 Error(s)
- `dotnet test SoulCore/SoulCore.Protocol.Tests` → all pass
- Do NOT start the Host — OPS will restart after build.
