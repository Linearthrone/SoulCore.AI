# TASK-110: Backfill missing episodic embeddings

## Context

QA-109 found episodic id 172 stored without a vector because `nomic-embed-text` was missing at write time. Older chat/self rows may also lack embeddings. Semantic recall only sees rows with vectors.

## Acceptance criteria

1. Add `IMemoryStore` method(s) to list episodics missing embeddings, e.g.  
   `Task<IReadOnlyList<(long Id, string Content)>> ListEpisodicsMissingEmbeddingsAsync(int limit, ct)`  
   — non-quarantined rows with no `episodic_embedding_vectors` row.

2. Add a Host evidence/CLI mode **or** PowerShell script under `SoulCore/scripts/` that:
   - Opens the live DB path (same default as MemoryOptions / from `/health`)
   - For each missing row (cap e.g. 200 per run): call Ollama embeddings (`nomic-embed-text`), `StoreEmbeddingAsync`
   - Prints counts: scanned / filled / failed
   - Prefer a script that uses the Host libraries via `dotnet run --project SoulCore.Host -- --backfill-embeddings [--limit N]` if easy; otherwise a focused C# console tool or script calling Ollama + Microsoft.Data.Sqlite is OK.

3. Idempotent: skip rows that already have vectors.

4. Best-effort: one failure must not abort the whole run (log and continue).

5. Document usage in the report. Optionally run once against the live DB and report how many were filled (including id 172 if still missing).

6. Do not change chat hot path beyond what's needed for ListMissing. No native sqlite-vec.
