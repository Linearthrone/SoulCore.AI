# TASK-103: Verify spend/token cap gate + E1 regression

## Context

BED-102 gates `chat.send` when `SpendMeter.CapExceeded` (USD cap **or** optional `MonthlyTokenCap`). Default `MonthlyTokenCap=0` (disabled). Live Host must be rebuilt/recycled with a low token cap for the gate test, then restored.

## Acceptance criteria

### Step 1 — Recycle Host with gate armed
1. Stop Host on :7700.
2. `dotnet build SoulCore/SoulCore.sln` (0 errors). Stop Host **before** build if DLL locked.
3. Start Host with env: `SOULCORE_Safety__MonthlyTokenCap=50` (and load `.env` as usual via `start-soulcore.ps1` or set env then `dotnet SoulCore.Host.dll`).
4. `/health` ok; note `safety.spend` fields. Confirm spend starts low.

### Step 2 — Trip the gate (E11)
5. Send `chat.send` frames (keep WS open until `chat.done` or `error`; timeout ≥180s). Repeat until tokens accumulate past 50 (SpendMeter estimates chars/4 — a few successful chats should suffice).
6. After CapExceeded, next `chat.send` must return **`error`** with `code: "chat.spend_cap"` (not chat.done with model text).
7. Host log Warning about spend cap.
8. Confirm **no new** episodic `source='chat'` row for the refused message (gate skips episodic write).
9. `/health` shows `safety.spend.capExceeded=true` (or token totals ≥ 50 with CapExceeded true).

### Step 3 — Restore + E1 regression
10. Stop Host. Unset/clear `SOULCORE_Safety__MonthlyTokenCap` (or set `0`). Restart with normal defaults.
11. Send "hello Victoria" → `chat.done` non-empty reply (E1 Pass).
12. Optional: E3 "move forward" → loco intent log (no regression).

### Step 4 — Report
Write `docs/agents/reports/TASK-20260724-103-QA01-to-PM01.md` with Pass/Fail per step and pasted evidence (frames, log lines, health JSON, sqlite counts).

## Environment
- Host: `http://127.0.0.1:7700` · `ws://127.0.0.1:7700/ws`
- DB path from `/health` → `memory.path`
- Do **not** leave MonthlyTokenCap=50 on the live Host after the test — restore to 0/default.
