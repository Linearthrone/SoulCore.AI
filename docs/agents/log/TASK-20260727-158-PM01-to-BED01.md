# TASK-158: Session history for tool continuity (ISSUE-004)

## Problem

`ChatWebSocketHandler` builds Ollama messages as **system preamble + current user text only**. Same-`sessionId` follow-ups like "what's the status of that task?" / "run that workflow" get no prior assistant/tool turns, so the model cannot resolve IDs. Blocks QA-142 AC2/AC6/AC7.

## Solution

1. Persist per-`sessionId` chat + tool message history (capped window — e.g. last N turns / token budget).
2. Pass that history into `CompleteWithToolsAsync` (or equivalent) on each `chat.send`.
3. Optional hardening: after `task_create` / `workflow_create`, inject recent ids into preamble — not a substitute for real history.
4. Do **not** write Victoria tasks into `docs/agents/tasks/` (PM tickets stay separate).

## Acceptance criteria

1. Same WS `sessionId`: create task → "what's the status of that task?" → model calls `task_get` (or `task_list` then get) with the created id — **no** clarification-only reply.
2. Same session: create workflow → "run that workflow" → `workflow_execute` with that id.
3. Re-run "workflow_execute" on completed workflow still returns reached-end / `Success:false` "workflow complete" (AC7 intent).
4. History is capped (document limit); new `sessionId` starts clean.
5. Unit/integration evidence + Host log excerpts in report.
6. Update ISSUE-004 status to Fixed when done.
