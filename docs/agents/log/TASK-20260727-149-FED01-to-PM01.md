## Storage API

| Data | API | File / name |
| --- | --- | --- |
| WS URL | Plain `SharedPreferences` | `companion_prefs` / key `ws_url` |
| API token | `EncryptedSharedPreferences` via `androidx.security:security-crypto:1.1.0-alpha06` | `companion_secure_prefs` / key `token` |
| Key material | `MasterKey.Builder` → `MasterKey.KeyScheme.AES256_GCM` | Android Keystore |
| Pref encryption | Key: `AES256_SIV`; Value: `AES256_GCM` | EncryptedSharedPreferences schemes |

One-shot migration: if a Phase-0 plaintext `token` remains in `companion_prefs`, it is moved into the secure store and wiped from plaintext on next `load()`.

Clear paths:

- `CompanionPrefs.clearToken()` — removes secure (+ any leftover plaintext) token only
- `CompanionPrefs.clearAll()` — clear token + reset URL to `DEFAULT_WS_URL`

## Auth headers (align BED-155 / SEC-152)

| Header | Role |
| --- | --- |
| `Authorization: Bearer <token>` | **Preferred** (Host `CompanionWsAuth` checks first) |
| `X-Api-Key: <token>` | **Alias** (also accepted by Host) |

Helper: `com.housevictoria.companion.net.CompanionAuthHeaders`

- `applyBearer(Request.Builder, token)`
- `applyApiKeyAlias(Request.Builder, token)`
- `redactForLog(token)` → `(no token)` or `(token present, len=N)`

`SoulCoreWsClient.connect` (FED-148) now calls both apply helpers when token is non-blank (same dual-header behavior as before, centralized). Empty token → no auth headers (loopback Host with unset `SOULCORE_COMPANION_API_TOKEN`).

`/health` probe remains unauthenticated (Host policy).
