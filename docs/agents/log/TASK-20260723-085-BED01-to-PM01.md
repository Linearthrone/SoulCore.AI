# TASK-085 — BED-01 — Report: Token generation limits added

## Summary

Added `MaxTokens` (default 256) to both `InferenceOptions` and `HermesOptions`, wired `num_predict` into the Ollama request payload (nested `options` object) and `max_tokens` into the Hermes chat completions payload, and updated both `appsettings.json` and `appsettings.Example.json`. All source compiles cleanly (0 warnings / 0 errors) and all 62 protocol tests pass.

## Changes

### F1 — InferenceOptions.MaxTokens

`SoulCore/SoulCore.Config/InferenceOptions.cs`

```csharp
public int MaxTokens { get; set; } = 256;
```

Added after `TimeoutSeconds`. XML doc references `num_predict` to map config → Ollama field.

### F2 — Ollama request: options.num_predict

`SoulCore/SoulCore.Inference/OllamaInferenceClient.cs`

- Added `OllamaGenerateOptions` nested class with `int NumPredict`.
- Added `OllamaGenerateOptions? Options` field to `OllamaGenerateRequest`.
- Payload construction now sets `Options = new OllamaGenerateOptions { NumPredict = _options.MaxTokens }`.
- The `JsonOptions` already uses `SnakeCaseLower`, so `NumPredict` serializes as `num_predict` and `Options` as `options`, matching the Ollama `/api/generate` schema.

### F3 — Hermes request: max_tokens

`SoulCore/SoulCore.Hermes/HermesHttpClient.cs`

- `ChatCompletionRequest.MaxTokens` already existed (nullable int) but was hardcoded to `256`.
- Changed to `MaxTokens = _options.MaxTokens` so it is config-driven.

### F4 — HermesOptions.MaxTokens

`SoulCore/SoulCore.Config/HermesOptions.cs`


Added after `TimeoutSeconds`, before `ApiKey`.
