# TASK-131: Memory tools — `recall_memory` + `store_memory`

## Problem

Today memory is host-injected into the preamble (`BuildContextPreamble` → `[Memory]`). The model cannot *decide* to recall a specific memory or store a new one. In LLMOD, `memory_store/retrieve/search` were LLM-callable tools. Restore that.

## Do not

- Do not change `IToolRegistry` types (BED-125).
- Do not change the tool-loop clients (BED-126/127).
- Do not remove the existing preamble-injected recall — keep it as the baseline context. The `recall_memory` tool is for **additional, model-initiated** recall within a turn.
- Do not implement body/system/fs tools (BED-132/133).

## Solution

Two `ITool` implementations registered as DI singletons:

### `recall_memory`

Wraps `IMemoryStore.RecallSimilarAsync` (semantic) and/or `RecallRecentAsync` (fallback when embeddings off).

```json
{
  "name": "recall_memory",
  "description": "Recall memories similar to a query. Use when you need to remember something specific.",
  "parameters": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "What to remember" },
      "limit": { "type": "integer", "description": "Max results (default 3)", "default": 3 }
    },
    "required": ["query"]
  }
}
```

Returns: `ToolResult(Success, Content: formatted memory snippets, Data: raw rows)`.

### `store_memory`

Wraps the episodic store (same path as `EpisodicMemoryPrompt` for model-authored memories — BED-108).

```json
{
  "name": "store_memory",
  "description": "Store a memory for later recall. Use for things the user says you should remember.",
  "parameters": {
    "type": "object",
    "properties": {
      "content": { "type": "string", "description": "The memory to store (first-person)" },
      "tags": { "type": "array", "items": { "type": "string" }, "description": "Optional tags" }
    },
    "required": ["content"]
  }
}
```

Returns: `ToolResult(Success, Content: "stored: id=N", Data: { id })`. Embedding is computed if `EmbeddingsEnabled=true`.

## Acceptance criteria

1. Both tools implement `ITool` and register in DI; `IToolRegistry.GetDefinitions()` includes them.
2. `recall_memory` calls `IMemoryStore.RecallSimilarAsync` when embeddings on, else `RecallRecentAsync`; returns formatted content the model can read.
3. `store_memory` writes a row with `source='model'` (not `'self'` — distinguish model-authored from loop-authored), computes embedding if enabled.
4. Both tools handle bad args (missing `query`/`content`) → `ToolResult(Success:false, Content:"error: ...")` — do not throw.
5. Unit tests: mock `IMemoryStore`, verify `recall_memory` returns seeded content; verify `store_memory` inserts a row with correct source.
6. No regression to preamble-injected recall (chat still works without the tool being called).
7. Report: file paths, schemas, sample tool_call + result, unit test evidence.
