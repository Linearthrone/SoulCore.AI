# TASK-130: Phase A exit gate — tool-loop round trip (recall_memory)

## Context

Phase A (agent-loop foundation) is done when the model **decides to call a tool**, the Host executes it, feeds the result back, and the model uses the result in its final reply. This is the first gate where Victoria exhibits agency.

## Test environment

- Host: `http://127.0.0.1:7700` · WS chat
- Ollama: `:11434` with `qwen2.5:14b` (BED-129 confirmed)
- `IToolRegistry` (BED-125) + Ollama tool-loop (BED-126) wired into ChatWS (BED-128)
- `recall_memory` tool (BED-131) registered and dispatching to `IMemoryStore.RecallSimilarAsync`

## Acceptance criteria

1. Seed a memory the model can recall (e.g. via `store_memory` or directly into SQLite): `"The user's favorite test phrase is QUOKKA-130."`
2. Chat message to Victoria: **"What is my favorite test phrase? Use your recall_memory tool."** (or a more natural prompt — your call; document exact prompt).
3. Capture raw `/api/chat` request/response from logs (Debug level) and verify:
   - Round 1: model emits `tool_calls[0].function.name == "recall_memory"` with a `query` argument.
   - Host executes `recall_memory` → returns `Success:true` with content including "QUOKKA-130".
   - Round 2: model receives `role:"tool"` result, emits final text containing "QUOKKA-130".
4. No infinite loop: total iterations ≤ `MaxToolIterations` (default 8).
5. No keyword side-effect double-trigger (per BED-128 strategy).
6. If model does not emit a `tool_call` after 2 prompt attempts with explicit instruction: file ISSUE; do not mark Pass.
7. Regression: E1 (speak) still works — Victoria still speaks her final reply via UnrealBridge (or at least `SpeakAsync` is called; UE may be down, log the call).
8. Evidence in report: prompt used, raw tool_call JSON, tool result, final reply text, iteration count, Pass/Fail. File ISSUE if Fail.
