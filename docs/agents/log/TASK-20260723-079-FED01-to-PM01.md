## Implementation Details

### Tab 1: Safety/Charter
- Read-only display of charter lock status (`CharterLockBox`), drift report status (`CharterDriftBox`), spend meter (`CharterSpendBox`).
- "View Charter Anchors" button toggles a placeholder text area (`CharterAnchorsPanel` / `CharterAnchorsText`) explaining anchors live in SoulCore.
- Matches existing TabItem template (underline accent on select).

### Tab 2: System
- Shows Host endpoint, bind address, port (from `ConnectionDefaults`).
- Shows inference provider (Ollama) status, Hermes status, memory DB path + open status, SoulLoop status, Unreal bridge target + connected status.
- "Refresh" button calls `GET /health` via the existing `ProbeHealthAsync()` then `ApplySystemStatus()`.
- Non-secret config only; secrets stay in `.env`.
- `ApplySystemStatus` null-guards ALL System tab controls (ISSUE-002 lesson) before writing — returns early if any are null during `InitializeComponent`.

### Tab 3: Voice/Video
- Static placeholder text: "Not configured (V1.1 target)" for voice, "Deferred to V1.1 parallel spike" for video.
- Disabled "Configure Voice" button (greyed out via `IsEnabled="False"` — opacity 0.45 from PrimaryButton template).
- Note: "Full-duplex audio is on the V1 path; WebRTC video is V1.1."

### Code-behind
- `RefreshSystem_Click` — async void, calls `ProbeHealthAsync()` then `ApplySystemStatus(_lastHealth)`.
- `ViewCharterAnchors_Click` — null-guards panel/text, toggles visibility.
- `ApplySystemStatus(SoulCoreHealthSnapshot)` — null-guards all 10 System + 3 Charter controls; populates from snapshot using the same `_okBrush`/`_warnBrush`/`_badBrush`/`MutedBrush` pattern as `ApplyUnrealStatus`.
- `NavSettings_Checked` — now calls `ApplySystemStatus(_lastHealth)` after showing the Settings view, so System tab shows last-known status without an extra network call.
- Reuses existing `HttpClient` + `JsonSerializerOptions` pattern via `_health.ProbeAsync()`.
