# TASK-108: Model-authored chat episodic

## Context

After a successful (non-stub) chat, `ChatWebSocketHandler` still writes a **template**:

```text
I heard the user say: …
I replied: …
```

North-star V1 requires the **model** to author a short first-person episodic memory. SoulLoop already writes `[Reflection]` as `source='self'`; chat episodes stay `source='chat'` but the **text** must be model-authored.

## Acceptance criteria

1. After `chat.done` and before/alongside embedding store, call inference (prefer the same provider that answered, or a short Ollama complete) with a **tight prompt**, e.g.:
   - System/instruction: Write 1–3 first-person sentences as Victoria’s private memory of this exchange. No meta, no quotes of the full reply. Past tense. Do not invent facts not present in the exchange.
   - User payload: include truncated user text + truncated assistant reply (budget ~800 chars total input).
   - Cap generation: use existing `MaxTokens` or a smaller override (e.g. 96) if easy.

2. Write the model output via `WriteEpisodicAsync(text, "chat", ct)` then existing embedding path.
   - If memory-authoring call fails or returns empty → **fallback** to the current template (Debug/Warning log). Never fail the chat path.
   - Skip memory-authoring entirely when `usedStub` is true (unchanged).

3. Prefix optional but recommended: keep content clearly episodic; do **not** require `[Reflection]` (that’s SoulLoop/self). Plain first-person is fine.

4. SpendMeter: record the memory-authoring call’s token estimate (same as other inference) so the spend gate stays honest.

5. Build + Protocol.Tests pass. Add a small unit test for any pure helper that builds the memory-author prompt / truncates, if extracted.

6. Do not change SoulLoop reflection, charter, or Unreal paths.

## Files (likely)
- `SoulCore/SoulCore.Host/Ws/ChatWebSocketHandler.cs`
- Optional helper in `SoulCore.Core` e.g. `EpisodicMemoryPrompt.cs`
- Tests under `SoulCore.Protocol.Tests`
