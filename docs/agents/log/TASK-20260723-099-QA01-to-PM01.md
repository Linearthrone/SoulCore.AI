## Observations (not failures — for PM-01 awareness)

### Observation A: "SoulLoop episodic reflection written" log is Debug-level, not Information

The task's acceptance check #2 says: "Check the host log for at least one
`SoulLoop episodic reflection written` log entry." However, this log line is emitted
at **Debug** level (`_logger.LogDebug` at `SoulLoopScaffold.cs` line 166), and the
default log level in `appsettings.json` is Information (`"Default": "Information"`).

Source evidence (`SoulLoopScaffold.cs` lines 161-168):
```csharp
try
{
    await _memory
        .WriteEpisodicAsync(reflection, "self", cancellationToken)
        .ConfigureAwait(false);
    _logger.LogDebug(
        "SoulLoop episodic reflection written: {Reflection}",
        reflection.Length > 80 ? reflection[..80] + "..." : reflection);
}
```

**Implication:** The host log CANNOT prove the E9 gate at the default log level —
the line is filtered out. The authoritative proof is the SQLite DB row (section 2d),
which unambiguously confirms the reflection was written. The E9 gate IS working; the
log line is simply not visible.

**Recommendation for PM-01:** If the task's acceptance criteria expect the
`SoulLoop episodic reflection written` line to be visible in the host log at the
default Information level, the log level at `SoulLoopScaffold.cs` line 166 should be
changed from `LogDebug` to `LogInformation`. This is a one-line change. Otherwise,
the DB query is the only proof path for this gate. This is NOT a BED-098 bug — the
reflection write works correctly; it's a log-visibility convention question.

### Observation B: Hermes returns 401 Unauthorized

The Hermes endpoint at `http://127.0.0.1:8642/v1/models` returns 401 Unauthorized.
The inference path correctly falls back to Ollama (which is the primary path since
`ChatWs:PreferHermes=false`). All 4 chat tests completed via Ollama. The Hermes 401
does not block the chat path but means the secondary failover path is unavailable.
This is the same environment state noted in prior tasks; not a BED-098 regression.

### Observation C: Thinking model produces verbose "Thinking Process:" output

The configured model (`Qwen3.5-9B-Claude-4.6-HighIQ-THINKING-HERETIC-UNCENSORED`)
is a thinking model that emits its reasoning as visible "Thinking Process:" text in
the reply. This inflates the token count (1024 output tokens across 4 chats) but
does not affect functional correctness. The model also takes ~37s on the first
(cold) request and ~3s once warm. Out of scope for TASK-099.
