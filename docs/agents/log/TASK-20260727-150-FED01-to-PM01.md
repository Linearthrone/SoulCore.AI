# TASK-20260727-150 FED-01 Report — Foreground service for background WS

## Verdict: **Pass**

Android companion now keeps the SoulCore WebSocket alive while backgrounded via a **dataSync foreground service** with a persistent low-importance notification. WS ownership moved out of Compose dispose into a process-scoped hub so navigating to Settings or leaving the Activity no longer tears down the socket. Stoppable from Settings and from the notification **Disconnect** action. `chat.done` local alerts are **not** implemented (FED-151).

## Architecture

| Piece | Role |
| --- | --- |
| `CompanionWsService` | FGS (`foregroundServiceType=dataSync`); `START_STICKY`; starts/stops WS; promotes with `ServiceCompat.startForeground` |
| `CompanionConnection` | Process-scoped hub: shared `SoulCoreWsClient`, `StateFlow` connection state, `SharedFlow` frames |
| `ConnectedNotification` | Channel + ongoing notification builder (IMPORTANCE_LOW, no sound) |
| Chat UI | Starts FGS on enter; observes hub flows; **does not** disconnect on leave |
| Settings | Save & reconnect; Disconnect; FGS status line; OEM caveat copy |

Permissions added: `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC` (existing `POST_NOTIFICATIONS` requested at connect on API 33+).

---

## Background lifetime (documented window + OEM caveats)

| Environment | Expected window |
| --- | --- |
| Stock Android (Pixel / AOSP) with FGS notification visible | **Hours** idle / screen-off; Doze does not immediately kill an active FGS socket |
| Aggressive OEM (Xiaomi / Huawei / Oppo / Samsung battery optimize) | May still freeze/kill after **hours–days** unless user exempts the app from battery optimization / allows autostart |

Keep-alive signal: OkHttp client `pingInterval(30, SECONDS)` (unchanged from FED-148).
