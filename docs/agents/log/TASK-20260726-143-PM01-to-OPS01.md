### 5. Ollama context ≥65,536 (amendment 2026-07-27 — HARD GATE)

Hermes refused tool use with:

> Ollama loaded `qwen2.5:14b` with only 32,768 tokens of runtime context, but Hermes needs at least 64,000 tokens for reliable tool use.

**Facts already observed:**

- Hermes (`%LOCALAPPDATA%\hermes\config.yaml`) already has `model.ollama_num_ctx: 65536` and `model.context_length: 65536`.
- `ollama show qwen2.5:14b` still reports `context length 32768`.
- SoulCore `appsettings.json` `Inference:NumCtx` is **32768** — Host warm-load can pin the shared Ollama instance at 32k and defeat Hermes.

**Required fix (pick a durable approach; document which):**

1. Ensure Hermes config retains `ollama_num_ctx: 65536` / `context_length: 65536` (create if missing on the active config path).
2. Raise Ollama runtime context for the chat model to **65536** — Modelfile `PARAMETER num_ctx 65536`, or a dedicated tag (e.g. `qwen2.5:14b-64k`), or equivalent documented mechanism.
3. Unload any 32k-loaded instance; reload; prove with `ollama show` / `/api/ps` that runtime context is ≥65536.
4. Bump SoulCore `Inference:NumCtx` (and Example) to **65536** so Host does not re-pin at 32k when sharing Ollama with Hermes. (Config-only; do not enable `Hermes.Enabled` — BED-144 owns that.)
5. Re-run a Hermes tool-call chat; confirm the 32k/64k warning is **gone** and tool_calls succeed.
