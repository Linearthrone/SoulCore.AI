# TASK-140: Task tools — `task_create` / `get` / `update_status` / `list`

## Problem

LLMOD had `task_create/get/update_status/list` so Victoria could manage her own work items. SoulCore has the `docs/agents/tasks/` folder convention (PM-authored tickets) but no model-callable task store. Give Victoria a lightweight task store she can write to and read from.

## Do not

- Do not change `IToolRegistry` (BED-125).
- Do not wire Victoria's task store into the PM ticket system (`docs/agents/tasks/`) — that's PM-authored, separate. Victoria's tasks are her own (a separate table or file). Document the separation.
- Do not implement workflow tools (BED-141).

## Solution

A lightweight task store (SQLite table `victoria_tasks` in the existing memory DB, or a JSON file — document choice) + four `ITool` implementations.

### Tools

```json
{ "name": "task_create", "description": "Create a task for Victoria to track.", "parameters":{ "type":"object","properties":{ "title":{"type":"string"},"description":{"type":"string"},"priority":{"type":"string","default":"medium"} }, "required":["title"] } }
{ "name": "task_get", "description": "Get a task by id.", "parameters":{ "type":"object","properties":{ "id":{"type":"integer"} }, "required":["id"] } }
{ "name": "task_update_status", "description": "Update task status.", "parameters":{ "type":"object","properties":{ "id":{"type":"integer"},"status":{"type":"string","description":"todo|in_progress|done|blocked"} }, "required":["id","status"] } }
{ "name": "task_list", "description": "List tasks (optionally filtered by status).", "parameters":{ "type":"object","properties":{ "status":{"type":"string"} } } }
```

### Storage

Prefer SQLite table `victoria_tasks(id INTEGER PK, title, description, status, priority, created_at, updated_at)` in the existing memory DB (`SqliteMemoryStore`). Add a migration `003_victoria_tasks.sql`. Reuse the connection.

## Acceptance criteria

1. All four tools implement `ITool`, register, appear in registry.
2. `task_create` inserts a row with `status='todo'`, returns `id` in `Data`.
3. `task_get` returns the row by id; missing id → `Success:false`.
4. `task_update_status` updates `status` + `updated_at`; validates status enum.
5. `task_list` returns all tasks, or filtered by status.
6. Migration `003_victoria_tasks.sql` is idempotent (`CREATE TABLE IF NOT EXISTS`).
7. Unit tests: create → get → update → list round trip; missing-id handling.
8. Report: storage choice (SQLite/JSON), schema, unit evidence, separation from PM tickets.
