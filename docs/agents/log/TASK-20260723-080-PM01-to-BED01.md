# TASK-080 — BED-01 — Charter/Safety library layer (soak-safe)

## Context

Phase 3 (Safety & Settings) is nearly unbuilt. The schema has `charter_anchors` table + `ICharter` interface exists but has no implementation. No drift watcher, no spend meter, no gate logic. This task builds the pure library layer — **soak-safe** (no Host restart, no DI wiring, no live-DB migration).

## Constraint

**Do NOT restart the SoulCore Host (`:7700`).** A 24h soak is running (PID 47288, expected end ~2026-07-24 01:31). All code in this task is pure library logic compiled independently. **Do NOT wire anything into `Program.cs` DI** or apply migrations to the live `soulcore_memory.db`.

## Scope

### F1: ICharter implementation

- Create `SoulCore.Core/Charter/CharterService.cs` implementing `ICharter`.
- Read `charter_anchors` from SQLite (use `SqliteMemoryStore` pattern or a new read-only connection factory that opens against a *temp* DB for tests).
- Return anchors by kind (identity/safety/value/boundary/ritual), filtered by `is_locked`.
- Support a `SeedAsync` method that inserts initial charter anchors (Victoria identity seed) — only callable from tests/staging, not wired to Host.
- Unit test: `SoulCore.Core.Tests` or `SoulCore.Protocol.Tests` — seed → read → verify locked vs unlocked.

### F2: DriftWatcher (report-only, no act-blocking yet)

- Create `SoulCore.Core/Safety/DriftWatcher.cs`.
- Track drift reports: when identity/emotion drift exceeds a threshold, generate a report (report-only; does NOT block acts yet — that's a future gate).
- Fields: `LastDriftReport`, `UnackedReports` count, `SloExceeded` (bool, computed from `LastDriftReport` age vs configured SLO).
- Method: `RecordDrift(DriftReport)` + `GetStatus()` → `DriftStatus`.
- No external dependencies; pure in-memory logic.
- Unit test: record drift → check status → verify SLO exceeded after threshold.

### F3: SpendMeter (token/cost tracking, no enforcement yet)

- Create `SoulCore.Core/Safety/SpendMeter.cs`.
- Track token usage per inference call: `RecordUsage(provider, tokensIn, tokensOut)`.
- Compute cumulative spend: `TotalTokensIn`, `TotalTokensOut`, `EstimatedCost` (configurable rate per 1K tokens; default $0).
- Method: `GetSummary()` → `SpendSummary` with monthly cap status ($30/mo default).
- No external dependencies; pure in-memory logic.
- Unit test: record usage → check summary → verify cap status flips at threshold.

### F4: No DI wiring

- Do NOT modify `Program.cs`. Do NOT register any new services.
- Do NOT modify `appsettings.json` (new config options can be defined in `SoulCore.Config` but not bound at runtime).
- All code must compile with `dotnet build SoulCore/SoulCore.sln` (excluding the locked-Host copy step which is environmental).
