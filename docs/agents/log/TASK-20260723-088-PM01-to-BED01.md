# TASK-088 — BED-01 — Add loco dispatch path to HandleChatSendAsync

## Context

QA-087 confirmed E1 (speak) PASSES — the speak + set_emotion forwarding works end-to-end. E3 (loco) still FAILS (hard-stop) because `HandleChatSendAsync` only calls `SetEmotionAsync` + `SpeakAsync` and never calls `LocoAsync`. The loco adapter (`UeVerbWireMapper.MapLoco` → `move_avatar_relative`) is wired and unit-tested but nothing in the Host invokes it.

ISSUE-20260723-002 is a P1 hard-stop. SoulLoop cannot be enabled until E3 passes.

## Scope

### F1: Add loco intent dispatch to HandleChatSendAsync

After the inference reply is received and `SpeakAsync` is called, add logic to detect locomotion intent in the chat text and call `LocoAsync`.

**Approach options (pick the simplest reliable one):**

1. **Keyword-based intent detection** — scan the user's original chat text for locomotion keywords ("step", "walk", "move", "forward", "back", "turn", "go"). If detected, call `LocoAsync` with a default forward movement (e.g., `forward=100, right=0, up=0`).

2. **New `loco.send` frame type** — add a dedicated WS frame type `loco.send` that the UI can send directly (bypassing the intent detection). This is cleaner but requires UI changes too.

**Recommendation: Option 1 (keyword-based) for now**, with a default movement of `forward=50, right=0, up=0` (50cm forward — a small step). This is the minimal change to clear E3.

### F2: Implementation

- Read `ChatWebSocketHandler.HandleChatSendAsync` to find where `SpeakAsync` is called (after the inference reply).
- After `SpeakAsync`, add a simple keyword check on the ORIGINAL user text (not the model reply):
  - If text contains any of: "step", "walk", "move", "forward", "back", "turn left", "turn right", "go" → call `_unreal.LocoAsync(forward, right, up)` with appropriate values.
  - Default: `forward=50, right=0, up=0` (50cm forward).
  - For "back" or "backward": `forward=-50, right=0, up=0`.
  - For "left": `forward=0, right=-50, up=0`.
  - For "right": `forward=0, right=50, up=0`.
- Wrap in try/catch (same pattern as SpeakAsync) — don't let loco failure break the chat path.
- Log the verb send (same pattern as the existing `speak` log line).
