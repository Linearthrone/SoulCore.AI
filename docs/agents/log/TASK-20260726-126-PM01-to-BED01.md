# TASK-126: Ollama native tool-loop (`/api/chat` with `tools`)

## Problem

`OllamaInferenceClient` calls `/api/generate` (or single-shot `/api/chat`) and returns text only. No `tools` array is sent, no `tool_calls` are parsed, no tool results are fed back. The model cannot decide to act.

## Do not

- Do not change `IToolRegistry` types (BED-125 owns those).
- Do not wire into `ChatWebSocketHandler` (BED-128 owns that).
- Do not implement Hermes tool-loop (BED-127 owns that).
- Do not implement concrete tools (BED-131+).
- Do not remove the existing single-shot `CompleteAsync` path — keep it as fallback for non-tool chat (e.g. simple reply, fallback when model lacks tool-calling).

## Solution

Add a **tool-loop inference method** to `OllamaInferenceClient` (or a new `OllamaAgentClient` — document choice). Use Ollama `/api/chat` with the `tools` field.

### Loop

```text
1. Host builds messages[] (system + user) and tools[] from IToolRegistry.GetDefinitions()
2. POST /api/chat { model, messages, tools, stream:false }
3. Parse response:
   - if response.message.tool_calls[] present and non-empty:
     for each tool_call:
       result = await IToolRegistry.ExecuteAsync(tool_call.name, tool_call.function.arguments, ct)
       append { role:"tool", name, content: result.Content } to messages
     go to step 2 (re-prompt with tool results)
   - else (no tool_calls, model emitted text):
     return response.message.content as final reply
4. Cap iterations at MaxToolIterations (default 8). If exceeded, return last text or a capped error.
```

### Ollama `tool_calls` format (verified)

```json
{
  "message": {
    "role": "assistant",
    "content": "",
    "tool_calls": [
      {
        "function": {
          "name": "recall_memory",
          "arguments": { "query": "what did we talk about yesterday" }
        }
      }
    ]
  }
}
```

`arguments` may arrive as a JSON object or a JSON string — handle both (Ollama has varied historically; parse defensively).

### Method signature

```csharp
public async Task<string> CompleteWithToolsAsync(
    IReadOnlyList<ChatMessage> messages,
    IReadOnlyList<ToolDefinition> tools,
    CancellationToken ct);
```

(Or extend `IInferenceClient` — coordinate with BED-127 so both paths share the same surface. If you add to `IInferenceClient`, update `NullInferenceClient` too.)

## Acceptance criteria

1. `CompleteWithToolsAsync` sends `/api/chat` with `tools[]`, receives `tool_calls`, dispatches via `IToolRegistry`, feeds `role:"tool"` results back, re-prompts, and returns final text.
2. Iteration cap enforced — no infinite loop if model keeps calling tools.
3. When model returns no `tool_calls` (just text), returns text immediately (1 round-trip).
4. Defensive `arguments` parse handles both object and string forms.
5. `NullInferenceClient` (and `appsettings Enabled=false` path) returns a deterministic stub reply without calling Ollama.
6. Logs each tool dispatch + result at Information; full loop at Debug.
7. Unit test: mock `IToolRegistry` + mock HTTP, verify one round-trip with a tool call, verify cap kicks in at N.
8. Report: method location (`OllamaInferenceClient` vs new client), `MaxToolIterations` default, evidence of a 1-tool-call round trip.
