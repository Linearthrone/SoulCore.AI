## Gate logic

```text
READ tools
  └─ AllowMt4Read? ──no──► Success:false "…enable AllowMt4Read"
                          yes
                           └─ IMt4Bridge.InvokeAsync(mt4_*)

WRITE tools (execute_trade / close_position / run_backtest)
  ├─ execute_trade only: sl present & >0? ──no──► Success:false "sl required…"
  ├─ AllowMt4Trade? ──no──► Success:false "…enable AllowMt4Trade"
  │                        (even if confirmed=true)
  ├─ confirmed=true? ──no──► Success:false "confirm trade: BUY 0.1 EURUSD…?"
  │                         (NO bridge call — phase 1)
  └─ yes ──► StripConfirmed → IMt4Bridge.InvokeAsync(mt4_*)
```

**Never** auto-executes a trade from a single model call. Phase-1 returns the confirm prompt; phase-2 with `confirmed=true` (after user agrees in chat) is required. Hermes path does **not** bypass these gates — gates run in the `ITool` layer before any bridge invoke.

### Confirmation prompt examples

| Tool | Phase-1 content |
| --- | --- |
| `execute_trade` | `confirm trade: BUY 0.1 EURUSD at market? reply yes to confirm` |
| `close_position` | `confirm close position: ticket 12345? reply yes to confirm` |
| `run_backtest` | `confirm backtest: MyEA on EURUSD from … to …? reply yes to confirm` |

### SL requirement

`execute_trade` rejects (before confirm and before bridge) when `sl` is missing, null, non-numeric, `≤0`, NaN, or Infinity. Message contains `sl required`.
