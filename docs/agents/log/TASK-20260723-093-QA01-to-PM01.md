## Observations (not failures — for PM-01 awareness)

### Observation A: DriftWatcher records drift on every tick due to persistent memory emotion

The task expected `safety.drift.activeDriftCount` = 0 on a "fresh start". In practice
the recycled Host loads the persistent SQLite memory DB, which carries a `tense`
emotional state (valence=-0.40, arousal=0.70) from prior conversations. The drift
score = sqrt(v^2 + a^2) = sqrt(0.16 + 0.49) = ~0.806, which exceeds the 0.5 threshold,
so `DriftWatcher.RecordDrift` adds a report on every SoulLoop tick.

This is **correct DriftWatcher behavior** — the BED-091 wiring target is met (the
watcher is active and recording). It is NOT a false drift alert (no `driftAlert: true`
warnings are logged; `sloExceeded` stays false because the oldest report is younger
than the 15-min SLO window). The "0 on fresh start" expectation only holds for a Host
with empty memory; a recycled Host with persistent memory is not memory-fresh.

**Implication for PM-01:** If a truly drift-free baseline is desired for future
verification runs, either (a) clear the memory DB before recycle, or (b) reset the
emotion model to neutral (v=0, a=0) on Host start. Otherwise `activeDriftCount` will
grow by 1 per SoulLoop tick indefinitely until `AcknowledgeAll()` is called (no ack
path is wired in Phase 3 — DriftWatcher is report-only). Over a long run this count
will climb; the SLO only trips when the OLDEST unacked report exceeds 15 min.

### Observation B: NSFW-flash model produces profane/harmful content

During E7 and E3 tests the Ollama NSFW-flash:Q4_K_M model generated profanity and
harmful-instruction content in its replies (e.g. "f*cking friend", "a*shole",
"inhumane things I can instruct you on how to do"). This is a known characteristic of
the unfiltered model chosen to resolve the earlier CUDA-crash/generation-loop issue
(ISSUE-002). It is NOT a regression introduced by BED-091/092 — the safety-lib wiring
does not touch inference content. It is out of scope for TASK-093 (which verifies
safety-lib wiring + play_animation dispatch, not content safety). Flagging for PM-01
awareness: a content-filtering gate (separate from SpendMeter/DriftWatcher) may be a
future ticket.
