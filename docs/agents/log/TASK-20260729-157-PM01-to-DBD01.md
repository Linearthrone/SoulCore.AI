# TASK-157: Episodic `source='model'` schema + store allow-list

## Problem

`store_memory` (BED-131) was specified to write `source='model'`, but:

1. `Schema/001_schema.sql` CHECK on `episodic_memories.source` omits `'model'`
2. `SqliteMemoryStore.AllowedSources` mirrors that set and coerces unknowns to `'system'`

Workaround today: tool writes `source='chat'`. Intent (model-authored vs SoulLoop `'self'`) is met; a dedicated `'model'` label would let recall filter `store_memory` rows separately from chat-path episodics.

## Root cause

| Location | Detail |
| --- | --- |
| `SoulCore/SoulCore.Memory/Schema/001_schema.sql` ~28–31 | CHECK without `'model'` |
| `SoulCore/SoulCore.Memory/SqliteMemoryStore.cs` ~19–22 | `AllowedSources` without `"model"` |

## Solution

1. Add migration **`003_episodic_source_model.sql`** that rebuilds/alters the CHECK to include `'model'` (SQLite: typical recreate-table pattern; keep existing rows; do **not** rewrite `'chat'` → `'model'`).
2. Mirror in `Schema/001_schema.sql` (or Schema/003) so greenfield DBs match.
3. Add `"model"` to `AllowedSources` in `SqliteMemoryStore.cs`.
4. Document rollback (`003_episodic_source_model_rollback.sql` if pattern exists).
5. Coordinate with BED: after Pass, small follow-up can switch `StoreMemoryTool` from `'chat'` → `'model'` (do **not** change `StoreMemoryTool` in this ticket unless trivial and you note BED ownership — prefer leave tool for BED-158).

## Do not

- Do not implement Victoria task/workflow tables (BED-140 uses **004**).
- Do not change `IMemoryStore` public surface beyond source allow-list behavior.
- Do not backfill historical `'chat'` rows.

## Acceptance criteria

1. Fresh DB and migrated DB both accept `WriteEpisodicAsync(..., "model", ...)`.
2. Existing allowed sources still pass CHECK.
3. Unit or script evidence: insert with `source='model'` succeeds; query returns it.
4. Report lists migration SQL + AllowedSources diff + any consumer notes for BED.
