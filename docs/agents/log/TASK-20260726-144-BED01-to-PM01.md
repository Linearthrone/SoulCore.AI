## Routing mechanism (chosen)

| Path | Role |
| --- | --- |
| `CompleteWithToolsAsync` (BED-127) | Chat agent-loop: model emits tool_calls → local `IToolRegistry` dispatch |
| **`CallMcpToolAsync` (BED-144, new)** | MCP-direct: SoulCore `ITool` adapters force a Hermes MCP tool via object-form `tool_choice`, Hermes executes server-side, content → `ToolResult` |

No separate Hermes MCP-direct HTTP endpoint was found/used — OpenAI-compatible
`POST /v1/chat/completions` with forced `tool_choice` is the invoke path.

### Server-side tool result translation

1. Probe `GET /health` (≤5s). Fail → `ToolResult(false, "hermes gateway unavailable")`.
2. `POST /v1/chat/completions` with single-tool `tools[]` + object `tool_choice`.
3. Prefer `choices[0].message.content`:
   - JSON `{success|ok, content|message|result|...}` → structured `ToolResult`
   - Plain text → `Success:true, Content=text`
   - Content matching ISSUE-001 `{name,arguments}` leak → `Success:false` (unevaluated call)
4. If content empty but `tool_calls` present → `Success:false` (client-side shape; ask for `tool_execution=server`).
5. `NullHermesClient` / missing API key / HTTP/transport errors → unavailable message (no silent native fallback when `Backend=hermes`).
