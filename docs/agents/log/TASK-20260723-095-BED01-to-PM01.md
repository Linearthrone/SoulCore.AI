## Approach

Created a standalone PowerShell script (`seed-charter-anchors.ps1`) that:

1. Resolves the DB path matching `MemoryOptions.ResolveDefaultDbPath()` (`$env:LOCALAPPDATA\SoulCore\memory\soulcore_memory.db`)
2. Confirms `sqlite3` CLI is on PATH and the DB + `charter_anchors` table exist
3. Counts existing rows — if > 0, reports current anchors and exits (idempotent)
4. If empty, writes a UTF-8 (no BOM) SQL file with a `BEGIN`/`COMMIT` transaction inserting all 10 anchors with `is_locked=0`, `source='seed'`
5. Executes via `sqlite3 .read` and verifies with a SELECT dump

The em-dash in the Purpose anchor body (`embodiment — a continuous self`) and
the apostrophe in the Name anchor (`Kayleigh's`) are handled correctly:
- Em-dash is constructed at runtime via `[char]0x2014` and written as UTF-8 (no BOM) so `sqlite3` reads it correctly
- Apostrophe is escaped as `''` (SQL standard) inside single-quoted string literals
- Script source is pure ASCII so it parses under PowerShell 5.1 (which reads non-BOM files as the system ANSI code page)

No C# code was compiled, no `dotnet script` was used, and the `CharterService`
class was not invoked directly — the script writes to the same DB file the Host
uses, matching the `SeedAsync` insert columns exactly.
