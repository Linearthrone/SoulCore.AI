# TASK-132: Body tools — `speak`, `play_animation`, `move_to`, `look_at`, `set_emotion`

## Problem

The 5 body verbs (`speak`, `play_animation`, `loco`/move, `look_at`, `set_emotion`) are keyword-detected side-effects off the **user's** text. Victoria never decides to wave, walk, or look. Promote them to real LLM-callable tools so the model can choose to act in her body.

## Cross-wave dependency

- **BED-114** (`BP_VictoriaCharacter` body host) and **BED-117** (AIController + `move_to` path-following) must land for `move_to` to produce a real walk.
- If embodiment slips, `move_to` may **teleport as interim** (current behavior) — but mark this clearly in the report and file a follow-up to switch to path-following once 117 lands.
- `speak`, `play_animation`, `look_at`, `set_emotion` work today via `IUnrealVerbClient` and do not block on embodiment.

## Do not

- Do not change `IToolRegistry` (BED-125) or tool-loop clients (BED-126/127).
- Do not change `IUnrealVerbClient` verbs themselves — wrap them.
- Do not remove keyword detectors — keep as fallback per BED-128.
- Do not implement Phase 2 gestures/gaze IK (separate Wave 27 Phase 2 work — BED-119/120/121/122).

## Solution

Five `ITool` implementations, each wrapping the existing `IUnrealVerbClient` method:

### `speak`
```json
{ "name": "speak", "description": "Speak text aloud with TTS.", "parameters": { "type":"object","properties":{ "text":{"type":"string"} }, "required":["text"] } }
```
Wraps `SpeakAsync`. Note: chat handler already auto-speaks final reply — this tool is for **additional** utterances the model wants to say mid-loop. Document the interaction (e.g. tool `speak` is for interjection, final reply is auto-spoken).

### `play_animation`
```json
{ "name": "play_animation", "description": "Play a body animation (wave, nod, etc.).", "parameters":{ "type":"object","properties":{ "name":{"type":"string","description":"e.g. wave, nod, wave_goodbye"} }, "required":["name"] } }
```
Wraps `PlayAnimationAsync`. Maps names to the same frame set as `DetectAnimationIntent` (12 keywords). Document the mapping.

### `move_to`
```json
{ "name": "move_to", "description": "Walk to a location.", "parameters":{ "type":"object","properties":{ "x":{"type":"number"},"y":{"type":"number"},"z":{"type":"number"} }, "required":["x","y"] } }
```
Wraps `LocoAsync` (relative offset) **or** a new `MoveToAsync` (absolute) if BED-117 added one. Until BED-117 lands, use `LocoAsync` with offset (interim teleport-style). Document.

### `look_at`
```json
{ "name": "look_at", "description": "Look at a target (player or world point).", "parameters":{ "type":"object","properties":{ "target":{"type":"string","description":"player | x,y,z"} }, "required":["target"] } }
```
Wraps `LookAsync`.

### `set_emotion`
```json
{ "name": "set_emotion", "description": "Set current emotion.", "parameters":{ "type":"object","properties":{ "emotion":{"type":"string","description":"neutral | happy | sad | angry | curious"} }, "required":["emotion"] } }
```
Wraps `SetEmotionAsync`.

## Acceptance criteria

1. All five tools implement `ITool`, register in DI, appear in `IToolRegistry.GetDefinitions()`.
2. Each tool wraps the corresponding `IUnrealVerbClient` method; returns `ToolResult(Success:true, Content:"ok")` on success.
3. When UE bridge is down (`UnrealBridge.Enabled=false` or WS closed), tools return `ToolResult(Success:false, Content:"unreal bridge unavailable")` — do not throw or hang.
4. `move_to` uses path-following if BED-117 landed; else documents interim teleport and files follow-up.
5. `play_animation` name mapping covers the same 12 keywords as `DetectAnimationIntent` (document mapping in report).
6. Unit tests: mock `IUnrealVerbClient`, verify each tool calls the right method with parsed args; verify graceful failure when bridge down.
7. Report: file paths, schemas, animation-name mapping, `move_to` mode (path vs teleport), unit test evidence.
