# TASK-141: Workflow tools — `workflow_create` / `execute` / `get`

## Problem

LLMOD had `workflow_create/execute/get` for multi-step plans. SoulCore has none. Give Victoria a simple workflow store: a workflow is a named list of steps (text + optional tool calls); `execute` advances the workflow one step (or runs to completion — document).

## Do not

- Do not implement a full DAG/dependency engine — keep it a simple ordered step list (LLMOD's was simple too).
- Do not change `IToolRegistry` (BED-125).
- Do not auto-execute workflows in SoulLoop (separate concern) — `execute` is model-initiated.

## Solution

A `victoria_workflows` table (or JSON) + three `ITool` implementations.

### Tools

```json
{ "name": "workflow_create", "description": "Create a multi-step workflow.", "parameters":{ "type":"object","properties":{ "name":{"type":"string"},"steps":{"type":"array","items":{"type":"object","properties":{ "description":{"type":"string"},"tool":{"type":"string"} }, "required":["description"]}} }, "required":["name","steps"] } }
{ "name": "workflow_execute", "description": "Execute the next step(s) of a workflow.", "parameters":{ "type":"object","properties":{ "id":{"type":"integer"},"all":{"type":"boolean","default":false} }, "required":["id"] } }
{ "name": "workflow_get", "description": "Get a workflow by id (with current step).", "parameters":{ "type":"object","properties":{ "id":{"type":"integer"} }, "required":["id"] } }
```

### Storage

SQLite table `victoria_workflows(id PK, name, steps_json, current_step, created_at, updated_at)` + reuse `SqliteMemoryStore`. Migration `004_victoria_workflows.sql`.

### `workflow_execute`

- `all=false`: executes the next step (calls the tool if specified, logs description), increments `current_step`, returns the step result.
- `all=true`: executes remaining steps in sequence, returns a summary.
- A step's `tool` field is the tool name to call (resolved via `IToolRegistry`); if missing, the step is just a description (no action).

## Acceptance criteria

1. All three tools implement `ITool`, register, appear in registry.
2. `workflow_create` parses `steps` JSON, stores, returns `id`.
3. `workflow_get` returns the workflow + current step index.
4. `workflow_execute` with `all=false` executes one step, calls the step's `tool` via `IToolRegistry` if present, returns the step result + new `current_step`.
5. `workflow_execute` with `all=true` runs remaining steps, returns a summary list.
6. Reached-end workflow returns `Success:false` with "workflow complete" (not an error).
7. Migration `004_victoria_workflows.sql` idempotent.
8. Unit tests: create → get → execute single → execute all; tool-call step; reached-end.
9. Report: schema, execute semantics (single/all), unit evidence.
