# TASK-159: Workflow step tool args (ISSUE-005)

## Problem

`workflow_execute` dispatches nested tools via `IToolRegistry.ExecuteAsync(toolName, {})`. Tools that need params (`recall_memory` → `query`, `speak` → `text`) always fail validation. Steps still advance `current_step`, so the workflow looks "done" without useful work. Blocks QA-142 AC6 nested-tool intent.

## Solution (preferred)

1. When executing a step with a `tool`, derive args from:
   - optional per-step `args` JSON on the workflow step schema (if adding fields, migrate carefully), **and/or**
   - a sensible mapping from step `description` into the tool's required fields (e.g. `query`/`text` = description when args empty).
2. Do not mark a step successful if the nested tool returns `Success:false` for required-arg validation (or surface clear failure without advancing as success — document chosen semantics).
3. Keep zero-arg tools working with `{}`.

## Acceptance criteria

1. Workflow with steps `recall_memory` + `speak` (descriptions non-empty): `workflow_execute` `all=true` → both nested tools succeed at contract level (`query`/`text` populated). Soft-no-op Speak when UE down is OK **after** accepting text.
2. Host log / tool Content shows no "requires 'query'" / "requires 'text'" for those steps.
3. Unit tests cover empty-`{}` regression and description→args path.
4. Update ISSUE-005 status to Fixed when done.
