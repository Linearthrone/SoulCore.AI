## Changes

### 1. DriftWatcher → SoulLoop tick

**File:** `SoulCore/SoulCore.Host/Loop/SoulLoopScaffold.cs`

- Injected `DriftWatcher` via constructor (6th parameter; already registered in DI by BED-082).
- In `TickAsync`, after computing the want string:
  - Calls `_driftWatcher.RecordDrift(label, fields, want)` inside a try/catch so drift
    recording can never break the loop.
  - Reads `GetStatus()`; when `SloExceeded` is true, logs a warning and sets `driftAlert = true`.
  - Adds a `driftAlert` boolean field to the `loop.want` frame payload.

**File:** `SoulCore/SoulCore.Core/Safety/DriftWatcher.cs`

- Added a convenience overload `RecordDrift(string emotionLabel, EmotionFields fields, string want)`
  that builds a `DriftReport` (Dimension="emotion", Score = √(v²+a²), Threshold=0.5,
  ObservedAt=UtcNow). Phase 3 is report-only so the exact score/threshold only affects
  `ExceedsThreshold` bookkeeping, not act gating.

**File:** `SoulCore/SoulCore.Core/Safety/DriftStatus.cs`

- Extended the record with a 4th field `OldestDriftReport` so `/health` can report
  `oldestDriftMinutes` (minutes since the oldest unacknowledged drift). The existing
  3-field constructor call sites in `DriftWatcher.GetStatus` were updated.

**File:** `SoulCore/SoulCore.Host/Loop/SoulLoopTickEvidence.cs`

- Updated both `new SoulLoopScaffold(...)` call sites to pass a `new DriftWatcher(15)`.

### 2. SpendMeter → Inference path

**File:** `SoulCore/SoulCore.Host/Ws/ChatWebSocketHandler.cs`

- `SpendMeter` was already injected (BED-082) and a `RecordSpend` helper existed, but it
  passed `tokensIn: 0, tokensOut: 0`. Replaced with real estimates:
  - `RecordSpend(provider, prompt, systemPreamble, reply)` now estimates tokens via
    `chars / 4` (industry rule-of-thumb) for both input (prompt + preamble chars) and
    output (reply chars), then calls `_spendMeter.RecordUsage(provider, tokensIn, tokensOut)`.
  - Both call sites (`ollama` path in `CompleteChatAsync`, `hermes` path in
    `TryHermesAsync`) updated to pass the prompt + preamble + reply text.
  - Entire call remains in try/catch — spend recording can never break chat.

Note: `IInferenceClient.CompleteAsync` / `IHermesClient.ChatAsync` return only the reply
string (no token counts). The chars/4 estimate is the best available proxy until the
response shapes expose `prompt_eval_count` / `eval_count` / `usage.prompt_tokens`. The
wiring is in place so real counts can be dropped in later without touching call sites.

### 3. DriftWatcher + SpendMeter → /health endpoint

**File:** `SoulCore/SoulCore.Host/Program.cs`

- Added a `safety` object to the health response:

- Both reads are wrapped in try/catch with safe fallbacks so `/health` never 500s if a
  safety singleton throws.
