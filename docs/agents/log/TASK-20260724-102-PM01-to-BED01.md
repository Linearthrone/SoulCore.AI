# TASK-102: Gate chat inference when spend cap is exceeded

## Context

`SpendMeter` records usage after each inference call and exposes `CapExceeded` on `/health`, but chat still calls the model even when the cap is tripped. North-star requires a **hard meter**. Local Ollama rates are `$0`, so cost alone never trips — add an optional **token ceiling** so the gate is usable offline.

## Acceptance criteria

1. **`SafetyOptions`**: add `long MonthlyTokenCap { get; set; } = 0;` (0 = disabled). Document in XML comments. Mirror in `appsettings.json` + `appsettings.Example.json` as `"MonthlyTokenCap": 0`.

2. **`SpendMeter`**:
   - Accept optional `monthlyTokenCap` in the constructor (default `0`).
   - `GetSummary().CapExceeded` is `true` when **either**:
     - `EstimatedCost >= MonthlyCap`, **or**
     - `MonthlyTokenCap > 0` AND `(TotalTokensIn + TotalTokensOut) >= MonthlyTokenCap`
   - Update the class XML comment: enforcement is now the caller's responsibility via CapExceeded; meter computes the flag including token ceiling.
   - Update `Program.cs` DI wiring to pass `safetyOptions.MonthlyTokenCap`.

3. **`ChatWebSocketHandler.HandleChatSendAsync`**: **before** `CompleteChatAsync`, call `_spendMeter.GetSummary()`. If `CapExceeded`:
   - Log at Warning: spend cap exceeded (include cost/cap and tokens/tokenCap from summary)
   - Send `error` frame: `{ code: "chat.spend_cap", message: "Monthly spend/token cap exceeded. Inference refused." }` with the chat.send correlation id
   - **Do not** call inference, write episodic chat memory, or Unreal verbs
   - Return early

4. **Unit tests** (`SoulCore.Protocol.Tests/SpendMeterTests.cs`):
   - CapExceeded flips true when token ceiling hit (rates can stay 0)
   - CapExceeded still flips on cost threshold (existing tests may need constructor arity update)
   - CapExceeded false when token cap is 0 (disabled) even with huge token counts

5. **Build + tests pass**: `dotnet build` / `dotnet test` on Protocol.Tests — 0 failures.

6. **Do not** change default live rates (keep 0) or live MonthlyCapUsd (30). Default MonthlyTokenCap=0 so production behavior unchanged until configured.
