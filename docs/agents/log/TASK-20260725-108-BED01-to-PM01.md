# TASK-108 report (BED-01 → PM-01)

## Summary

After non-stub `chat.done`, Host now asks the same chat provider (Hermes or Ollama) to author a short first-person episodic memory, then writes that text via `WriteEpisodicAsync(..., "chat")` and keeps the existing embedding path on the returned episodic id. Empty/failed authoring falls back to the legacy `I heard the user say:` template with a Warning log; stub chats still skip memory entirely.

## Approach

1. **`EpisodicMemoryPrompt`** (Core) — pure helper: system instruction, ≤800-char truncated exchange payload, template fallback, `AuthorMaxTokens = 96`.
2. **`AuthorChatEpisodicAsync`** in `ChatWebSocketHandler` — prefer provider that answered; else Ollama if enabled; else Hermes. Cap generation at 96 tokens. `RecordSpend` on success. Never throw into the chat path.
3. **Inference APIs** — optional `maxTokens` on `IInferenceClient.CompleteAsync` / `IHermesClient.ChatAsync` (null → configured MaxTokens).
4. SoulLoop `[Reflection]` / charter / Unreal paths untouched.

## Sample authored memory (fixture)

```text
Kurt asked about the garden plans. I told him the roses still needed pruning this weekend.
```

(Not a live Ollama dry-run; Host was down. Unit fixture asserts this shape is plain first-person and does **not** start with `I heard the user say:`.)
