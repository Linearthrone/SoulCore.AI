# TASK-20260727-155 BED-01 Report — Fail-closed `/ws` companion token gate

## Behavior

| Condition | `/ws` upgrade |
| --- | --- |
| `SOULCORE_COMPANION_API_TOKEN` **unset** / whitespace | Accept (loopback desktop trust) |
| Token **set**, no auth header | **401** `Unauthorized` — no `AcceptWebSocketAsync` |
| Token **set**, wrong Bearer / X-Api-Key | **401** `Unauthorized` |
| Token **set**, `Authorization: Bearer <match>` | Accept |
| Token **set**, `X-Api-Key: <match>` | Accept |

Canonical env name: **`SOULCORE_COMPANION_API_TOKEN`** (`SecretNames.CompanionApiToken`). Recommended length ≥ **32** random chars (documented in `.env.example` / `appsettings.Example.json` / README — not hard-enforced at runtime).

Resolution order: process env (DotEnv / shell) → configuration (`SOULCORE_COMPANION_API_TOKEN` or stripped `COMPANION_API_TOKEN` for user-secrets).

`/health` remains unauthenticated on loopback and does **not** include the token or auth status secrets.
